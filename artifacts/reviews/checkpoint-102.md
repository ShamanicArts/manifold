# Checkpoint 102 — sample-clocked MIDI Arpeggiator

Open [MIDI Arpeggiator](http://127.0.0.1:4173/?primitive=midi-arpeggiator). Start audio, hold C4 and E4 on the on-screen keyboard, then try Up, Down, Ping-pong, and Random, change Octaves and Gate length, and turn Hold on before releasing the keys. The incoming list shows keyboard events; the Rust output list shows generated notes, velocity, channel, and offset within each audio block. The keyboard works without hardware MIDI permission. Use Copy URL under Hardware MIDI to open the same view in an external browser when the embedded view blocks permission.

The [typed Rust graph](../../crates/manifold-core/src/graph.rs) now renders up to each incoming MIDI event or internal arp deadline. A deadline on a block boundary executes at offset zero of the next block. The [fixed-capacity Arp kernel](../../crates/manifold-core/src/midi_arpeggiator.rs) holds up to eight input notes, expands a 32-step sequence, and owns eight output lanes. The browser uses [project controls](../../projects/midi-arpeggiator/project.json) for rate, mode, octaves, gate, and Hold. Random uses a fixed seed for repeatable rendering.

The [legacy callback comparison](checkpoint-102-midi-arpeggiator-events.json) records the original Lua adapter's C4 on, C4 off, and E4 on in callbacks ending at frames 1536, 5248, and 7552. V2 emits them at exact frames 1440, 5040, and 7440. The [migration note](../../docs/midi-arpeggiator-migration.md) explains the timing and Hold decisions. This is a legacy Lua event comparison and native Rust audio reference, not a C++ audio capture.

Verification: three old Lua rack tests pass; 106 Rust core tests pass, including identical arp audio and event frames at 64-, 128-, and 256-frame blocks and Hold enabled while notes are already pressed. Four 32,768-frame stereo cases match native Rust against direct Wasm, the actual AudioWorklet adapter, and the browser comparison renderer with maximum sample difference 0. The cases cover [chord capture and all-notes-off](checkpoint-102-midi-arpeggiator-chord-capture-metrics.json), [held ping-pong](checkpoint-102-midi-arpeggiator-held-pingpong-metrics.json), [held down with short gates](checkpoint-102-midi-arpeggiator-held-down-short-gate-metrics.json), and [seeded random](checkpoint-102-midi-arpeggiator-held-seeded-random-metrics.json). The MIDI scheduling, permission-request, CV rack, sample-instrument, and limiter regressions pass, as does the Vite build. The served page has 50 views and 392 cases, and its Wasm matches the tested module. Hardware MIDI is untested in the embedded browser because its permission policy may block the API; the keyboard and Rust event path are testable there.
