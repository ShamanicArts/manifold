# Review checkpoint 13: stereo delay and persistent buffers

Date: 2026-09-26. Open the [live Stereo delay workbench](http://127.0.0.1:4173/?primitive=stereo-delay). Review the [desktop](checkpoint-13-1365.png) and [mobile](checkpoint-13-390.png) captures. The page has live controls and playback, a full-tail plot for both stereo channels, C++/Rust/difference listening, and eight selectable comparisons.

The graph now owns a `StereoDelay` node with two five-second f32 ring buffers allocated at prepare time. It ports the legacy fractional taps, 20 ms time smoothing, 10 ms continuous-control smoothing, feedback, crossfeed, width, ducking, one-pole feedback lowpass, free/synced beat divisions, tap-time swap, freeze, and dormant bypass. Processing allocates no buffers. The authored project graph uses the same Rust kernel in native and Wasm builds. The old JUCE node is compiled through a standalone runner in this repository; the old checkout remains untouched.

All eight checked-in C++ cases match native Rust sample for sample for fractional tap periods: stereo echo, time sweep, crossfeed, ping-pong/width, filtered ducking, tempo sync, freeze, and dormant bypass. All 61 browser comparisons across eleven views show **Match**, with no page errors. `cargo test --workspace` passes 22 tests, including an impulse spanning a block boundary. The live AudioWorklet runs at 48 kHz in Chromium; desktop and 390 px mobile layouts have no horizontal overflow.

**Intentional correction:** the original C++ read index wraps by ring size, but its interpolation fraction uses the unwrapped position. At an exact tap boundary this can produce a large spike. A 0.6 impulse with a 10 ms wet tap at 48 kHz produced a peak of **100,799.59** in C++, versus **0.42** in Rust. Rust wraps the position before taking its fraction. The parity fixtures use fractional tap periods so they assess the behavior outside that defect; the Rust unit test covers the corrected boundary. The exposed resonance control is preserved for API parity, but the old one-pole feedback filter does not use resonance, so it has no audible effect.
