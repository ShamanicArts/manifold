# Review checkpoint 26: file-backed sample region

Date: 2026-09-26. Open the live [Sample region workbench](http://127.0.0.1:4173/?primitive=sample-region). Start the instrument and click **Trigger sample** to hear the built-in example. Choose a local audio file to replace it; the page reports decoded duration and channel count, and a running instrument must be restarted to load the replacement. Speed, reverse, one-shot, and region bounds are editable. The comparison panel offers five native Rust/Wasm cases: forward loop, one-shot end, reverse region, region/speed change, and timed note retrigger.

The browser decodes file bytes outside the audio callback at 48 kHz, up to 30 seconds and 32 MB. The worklet reserves up to 1,440,000 interleaved stereo frames in Wasm, copies the decoded data once, and commits it to the Rust graph before reporting ready. The Rust node owns this buffer and reads it with linear interpolation; `process` has no allocation or file I/O. This is a first file-backed slice of the old Standalone Sample project, not the whole eight-voice instrument. Crossfade, unison, capture transfer, analysis, and preset/state transfer remain open; see the [migration boundary](../../docs/standalone-sample-migration.md).

Validation: 36 Rust tests passed. All **123 workbench cases** showed Match with no page errors (76 C++ and 47 native Rust references). The actual worklet adapter passed a sample upload, note trigger, and stereo loop smoke check. A headless browser decoded a 0.10 s mono WAV, reported it ready, started the sample instrument at 48 kHz, and sent a trigger without page errors. A normal automated click stalled under the host Chromium compositor issue, so that browser check used a DOM click. In response to the MIDI visibility report, the Voice view now places **Request MIDI access** above the parameter stack: the button begins at y=331 in a 768 px tall desktop viewport, compared with y=766 before. A mocked browser permission API was called exactly once on click and reported access granted with no devices. The in-app browser automation backend did not expose a controllable browser session; no physical MIDI connection or permission prompt was verified there. The button reports policy blocks or denials where the browser exposes them.
