# Review checkpoint 29: eight-voice sample instrument

Date: 2026-09-26. Open the live [Sample instrument workbench](http://127.0.0.1:4173/?primitive=sample-instrument). Click **Start instrument**, then play the on-screen keyboard or use A–K and nearby black-key shortcuts. The built-in half-second sample works immediately; stop the instrument to choose an audio file. The [waveform capture](checkpoint-29-waveform.png) shows a two-note chord with independent playheads. The page exposes the transport, MIDI request, keyboard, and sample source before the parameter list.

Eight Rust voice cursors share one immutable decoded stereo buffer. Timed note events carry channel, note, and velocity; matching note off releases only that key, a ninth note steals the oldest voice, and root note plus key tracking set resampling speed. Region, reverse, one-shot, and crossfade controls apply to every voice. A nine-value meter reports active voice count and playhead positions without routing drawing through the audio callback.

Decisions to review: v2 key tracking is continuous from 0 to 1 while the legacy classic mode used an on/off switch. Note off currently stops a voice immediately, which can click; a short release envelope belongs in a later slice. The dynamic source slot, live/sidechain capture into the instrument, phase vocoder pitch modes, unison/detune/spread, and sample analysis are still outside this slice. The six new fixtures compare native Rust with Rust/Wasm and make no claim of complete C++/Lua project parity.

Validation: `cargo fmt --all -- --check`, 40 Rust tests, the sample instrument worklet smoke (one upload, two notes, targeted note off, nine-value meter), and all **131** offline browser cases passed (76 C++ and 55 native Rust; six new instrument cases). In a 390 × 844 browser viewport the Start button, MIDI request, and keyboard were visible without horizontal overflow. Live two-note playback showed **2 / 8 voices**, two event entries, and the expected **0 / 8** after release, with no page errors. The application's simulated Web MIDI event path passed separately; hardware MIDI permission and device access in the in-app browser remain unverified.
