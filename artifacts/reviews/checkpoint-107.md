# Checkpoint 107 — first Main sample blend study

Open the [playable Main blend](http://127.0.0.1:4173/?primitive=main-sample-blend) and the [checkpoint review](http://127.0.0.1:4173/main-sample-blend-review.html). The workbench loads a built-in source automatically or accepts an audio file. Select Source, Add self, Add driven, or Morph; prepare the target, start audio, then vary sample and Sine branch levels. The reference drawer offers four native Rust versus direct Rust/Wasm graph captures.

The [authored project](../../projects/main-sample-blend/project.json) combines a stereo sample region, prepared Sine bank, and two-input mixer. It derives from the old `Main/lib/sample_synth.lua` branch layout but is deliberately a smaller graph. The [worklet verifier](../../scripts/verify-main-sample-blend-worklet.mjs) uses one deterministic source for both sample upload and Rust/Wasm temporal analysis; both branches and their blend produce audible, finite output. A headless Chromium interaction confirmed the browser view starts the instrument and prepares a Morph target.

The [native Rust renderer](../../crates/manifold-core/examples/render_main_sample_blend.rs) analyzes a fixed source, prepares Add or Morph partials, and renders the same graph. The [fixture generator](../../scripts/generate-main-sample-blend-reference.py) records four 16,384-frame stereo cases: sample only, Add only, Morph only, and equal-gain sample plus Morph. The [comparison verifier](../../scripts/verify-main-sample-blend-comparison.mjs) renders the graph through Wasm with the exact same source and target assets; all four have zero maximum sample difference and nonzero RMS. This proves graph playback parity for those assets. Separate checkpoint 106 evidence covers old C++ recipe semantics; this graph fixture does not claim old Main project parity.

Verification: 114 Rust workspace tests, native fixture regeneration, direct Wasm four-case comparison, Main AudioWorklet branch verifier, Vite build, and browser interaction. The old Main graph still includes phase vocoder playback, envelopes, several crossfades, MIDI voice behavior, and saved state. Those are the next reconstruction tasks.
