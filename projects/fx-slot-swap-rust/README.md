# FX slot swap in Rust

This is a separate project crate that depends on Manifold's public Rust authoring API. It ports the control flow in the legacy `DspLiveScripting/dsp/fx_slot_swap_harness.lua`: two serial effect slots start with gain instances, remember inactive effect amounts, and instantiate a stereo widener only when selected. The graph is built from ordinary gain, sum, and widener primitives. The equivalent JS project module is [`fx-slot-swap.mjs`](../../packages/manifold-author/examples/fx-slot-swap.mjs).

`FxSlotSwap::new()` builds the graph. A host retains the `FxSlotSwap` value on its control side, calls `prepare_set(rate, max_frames, path, value)` for each project control event, and submits the returned prepared transaction to `publish()` at a block boundary. The returned old runtime and graph are retired off the audio callback. `to_project()` provides a portable snapshot. After a host save, `FxSlotSwap::from_project_json(bytes)` restores the handler and its inactive control values without opening an editor.

Project controls resolve saved instance paths such as `/test/fxslot/slotA/nodes/gain_gate`; numeric IDs are only the default graph's construction details. A newly selected effect takes its preferred ID when free or another free ID when occupied. The Rust and JS handlers restore paths when reopening the earlier FX slot snapshot format that had no `instances` array.

Run `cargo test -p manifold-fx-slot-swap` from the repository root. The tests compare the Rust graph to both JS-authored fixtures, check that gain and width values are audible from sample zero, hear the structural selection change through the native engine, save and reopen the selected graph, and change selection again. They also renumber saved nodes and occupy the preferred new IDs, then compare the rendered result against the original graph. The browser can audition the same fixtures at [`fx-slot-swap.html`](../../web/fx-slot-swap.html).

The CLAP and VST3 hosts can import both authored snapshots while active and now preserve eligible gain and stereo widener state by matching named paths at publication. They do not yet dispatch project control events to this crate. The browser worklet still needs safe off-callback structural preparation and publication. Rust authoring transactions also match saved instance paths when numeric node IDs change. Unnamed nodes can retain history by ID when that ID has no conflicting named identity. New gains fade in. Other stateful primitives still need continuity rules.
