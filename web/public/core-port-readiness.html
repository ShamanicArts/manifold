Manifold v2 / core port audit / 28 September 2026

The engine has grown.
The rack contract is still missing.

Rust/Wasm audio, typed graph primitives, browser playback and Linux CLAP/VST3 hosts are real. They are not yet enough to transpose an arbitrary Manifold project without new one-off integration. The Main MidiSynth rack and Patch environment are the decisive gap.

Current verdict: core transposition gate open.

The old Patch view shows port panels in the same rack shells and draws editable cables between them. The current Main page has fixed module positions and selector controls. Its former “Patch” button only scrolled to those controls; it has been renamed “Routes.” A visible module face is evidence of widget work, not of a portable rack architecture.

What Patch actually means

Legacy Main

One rack, two faces

Module instances have row, column, size and stable identity. Rack mode shows instrument controls. Patch mode replaces each active face with typed Audio/CV/MIDI ports. Wires, rail terminals, snapping, deletion, palette insertion, drag/reorder and width changes operate on saved module and connection state.

Current v2 Main

Fixed faces and route selectors

Many instrument widgets and DSP routes work. Placement is hard-coded in CSS; state is a fixed collection of module fields. Up to four LFO slots and a few prepared routes can change. There is no general module list, port cable state or Patch face switch in this page. Shell delete, drag and resize controls are missing.

Build order

  1. Define the project document and importer. The first versioned rack document now captures the legacy default and validates typed module, layout and wire edits. Import of older Main sessions remains.
  2. Compile a small audible Main route from that document. The first audio route proof now compiles the six-module default into a separate Graph host project: changing the Filter cable changes native and Wasm audio. The browser Graph workbench imports and starts this project. One CV cable, safe live plan publication and Main looper integration remain.
  3. Rebuild the shell and Patch projection. Port actual widget faces and headers. Make drag, width, delete and cable gestures edit the same document and audible route.
  4. Close browser/native state roundtrips. Reopen a modified rack with identical layout, wiring and sound in both plugin formats.
  5. Port two unlike reference projects through the same path. If they require another bespoke rack/runtime, the core gate has not passed.

After these gates, specialized project DSP and visual modules may still need work. The claim would be that the environment can carry them without architectural reinvention.
