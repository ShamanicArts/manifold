The engine has grown.
The rack contract is still incomplete.

Rust/Wasm audio, typed graph primitives, browser playback and Linux CLAP/VST3 hosts are real. They are not yet enough to transpose an arbitrary Manifold project without new one-off integration. The Main MidiSynth rack and Patch environment remain the decisive gap.

Current verdict: core transposition gate open.

The old Patch view shows typed port panels in movable rack shells and saves their editable cables. Main now switches six prepared shells between controls and a limited audio Patch face: audio cables can be dragged or unplugged and change the running Wasm graph. The former “Patch” scroll button is labelled “Routes.” The six-module audio cables now save and reopen in a version-16 Main session; six-shell grid dragging now saves and reopens; broader port behavior remains.

What Patch actually means

Legacy Main

One rack, two faces

Module instances have row, column, size and stable identity. Rack mode shows instrument controls. Patch mode replaces each active face with typed Audio/CV/MIDI ports. Wires, rail terminals, snapping, deletion, palette insertion, drag/reorder and width changes operate on saved module and connection state.

Current v2 Main

Six prepared audio faces

The document records stable modules, layout and typed wires. Six browser shells switch to port faces; supported audio sockets can be cabled and uncabled live. Browser shells use saved grid positions and support drag with live row reflow and a utility strip that follows added audio rows; CV/voice ports are display only. Edited audio cables and positions save in the version-16 Main session. The packaged CLAP state probe and VST3 component state test pass. An isolated host clicked the real CLAP child editor's Rack/Patch control and physically dragged Source onto Filter; the saved state retained the swapped positions and cables. A VST3 child editor Rack/Patch toggle and REAPER state reopening pass; physical VST3 child dragging remains. The Filter now has a saved compact width toggle; remaining header actions, module insertion/removal and other sizes remain open.

Build order

  1. Complete the project document and importer. The first versioned rack document captures the legacy default and validates typed module, layout and wire edits. Version-16 Main import/export retains six-module audio connections and grid placement; broader ports remain.
  2. Extend the authored route in Main. The Main insert proof runs after Main's voice bank and before looper capture. The browser audio Patch rewires six prepared nodes live. New nodes, DAW proof and full CV/voice behavior remain.
  3. Complete the shell and Patch projection. Restore original headers and widget faces. Extend the working drag and Filter width control to other real faces, delete and palette edits, with matching host behavior.
  4. Close browser/native state roundtrips. Reopen a modified rack with identical layout, wiring and sound in both plugin formats.
  5. Port two unlike reference projects through the same path. If they require another bespoke rack/runtime, the core gate has not passed.

After these gates, specialized project DSP and visual modules may still need work. The claim would be that the environment can carry them without architectural reinvention.
