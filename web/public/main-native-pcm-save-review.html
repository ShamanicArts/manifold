The transfer

1. RequestControl asks for a snapshot. Recording and pending commits must have ended.
2. MarkAudio publishes one transport and layer header at a block boundary.
3. CopyAt most one 4,096-frame stereo chunk moves into a prepared buffer per block. Two buffers absorb control-side delays.
4. AssembleControl collects exact-size loop and sample vectors and checks every sample before returning them.

What was proved

Chronological PCMA 9,000-frame loop and Main Sample cross several chunk boundaries and return their first, middle, and final samples in order.
No callback waitWhen both chunks are in flight, audio processing proceeds and copying resumes after control returns a buffer.
Concurrent endpointsA separate audio thread renders while the control thread polls and assembles the snapshot.
CancellationA loop command or prepared session publication interrupts the old capture; recording rejects it before copying.

The full Rust workspace suite passes. The transfer allocates chunk buffers during preparation and assembled PCM on the control side.

What remains

This milestone returns PCM and transport metadata. A complete Main session save still needs coherent rack controls and UI-only product state assembled into the browser's version-15 JSON, then a native plug-in state callback and reload probe. Main CLAP and VST3 classes are not yet registered.
