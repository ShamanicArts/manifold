Manifold v2 / project state checkpoint / 27 September 2026

A browser sampler project now opens in native Rust.

The native processor can load the live sampler and sidechain sampler projects authored in the browser. Graph routes, initial controls, and embedded stereo samples reach the same prepared Rust DSP engine used by Wasm.

The state path

01 · BrowserGraph project

Typed nodes, routes, authored parameter values, and optional sample PCM are saved as a v1 project bundle.

02 · Native control threadValidate & decode

The Rust loader checks version, shape, bounds, node kinds, parameters, and PCM before preparing audio.

03 · PrepareCompile & install

It compiles the graph, restores controls, and loads the sample outside the audio callback.

04 · Audio threadRender

Main and sidechain buses and timed MIDI enter the prepared native processor.

Evidence from the checkpoint

2browser sampler templates opened by native Rust
1embedded stereo PCM asset restored and played by MIDI
147passing Rust workspace tests, including 7 native tests

One test renders the saved sidechain graph with the authored main gain. Another decodes an embedded sample, sends a timed MIDI note through the restored route, and confirms the note sounds after its offset. Malformed versions, parameters, and PCM are rejected.

This covers the sampler graph slice. Other graph nodes, nonempty partial targets, and temporal recipes return an explicit unsupported error. The browser's oscillator and microphone source choices describe its own test setup; a native host supplies the buses.
