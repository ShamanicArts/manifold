The direct Wasm test applies both route changes between blocks while Main keeps processing. The graph retains prepared kernels and recomputes reachability without allocating. A reverse EQ-to-Filter edge is rejected. The browser audio Patch face now calls this operation for its prepared nodes; version-16 sessions now save and reopen these six-module audio cable edits.

This remains a bounded Main insert proof.

The browser Main page now prepares the selected audio connections at startup and can rewire the six prepared audio nodes while processing. It can move the six fixed-size browser shells and save their placement; it cannot yet add or remove modules; the CV and voice sockets shown on its Patch face are inactive. Main version-16 native sessions now prepare the saved audio insert before publication; their packaged editors display this Patch face read only. Wasm rejects graph replacement after processing starts because compilation on the AudioWorklet thread would interrupt audio. Native editor layout messages now reach CLAP and VST3 control state; shell resizing and general plan publication remain. Browser and native Rust now save the six-module audio routes in Main v16; a packaged DAW roundtrip remains. The insert's Graph LFO also differs from Main's six-shape LFO, so their control and status models must be reconciled before exposing that cable in the editor.

The Wasm memory buffer grows from 242 MiB after fixed Main preparation to 283.2 MiB with the insert at 48 kHz and 128-frame capacity. The fixed Filter/FX/EQ processors are still allocated as control shadows. Consolidating that ownership is part of the core runtime work.
