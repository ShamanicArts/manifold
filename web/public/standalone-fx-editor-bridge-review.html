The ported widgets now open inside CLAP.

The loadable Linux CLAP module starts a separate WebKitGTK editor in the host's X11 parent window. It renders the same ui.json and Canvas slider and dropdown code as the browser page. This is a capture of that native child window after a CLAP state load selected Reverb with Mix 0.72, Room 0.80, and Damp 0.30.

What is proven

Widget identity
The native editor and browser module execute the same project-ui.js Canvas renderer for compact sliders, dropdowns, and the XY pad.
Host input
A real CLAP state stream loaded seven public controls plus 21 remembered effect sets. A subsequent CLAP parameter event changed Mix from 0.72 to 0.20 in the same native window, shown in the second capture.
Window lifecycle
A disposable X11 host exercised create, parent, show, hide, and destroy. The editor ran in a companion process; no GTK loop entered the DSP module.
Host output
The browser widget test emits begin, value, and end IPC messages. A CLAP host test checks their event forms and retry behavior. Synthetic pointer input was unavailable in the isolated Xwayland compositor, so the full physical pointer to native host chain still needs a manual DAW or Xvfb test.
Audio boundary
The CLAP audio callback continues to use prepared native Rust DSP. Editor state and IPC are handled outside it.
Independent validator
After adding the GUI extension, CLAP validator v0.4.1 still passed all 33 applicable tests, with zero failures and 11 skips. Its suite did not exercise the GUI window.
