One block, four steps

1. CheckValidate offsets, order, MIDI, values, IDs, and command arguments before rendering.
2. RenderRun audio to the next event offset using prepared buffers.
3. ApplyChange Main state at the exact frame; continue rendering the rest of the block.
4. PublishAfter a valid block, publish any separately prepared browser session for the following block.

What works

Looper controlsTransport IDs 0–5, four layer ranges, and command IDs 0–9. First Loop record and stop actions were tested inside one 128-frame block.
Instrument controlsSource, ADSR, Filter, both FX slots, eight-band EQ, and Arpeggiator. Tests change Master and Arpeggiator connection at frame 64.
Failure boundaryA later invalid value rejects the entire queue before the earlier record command or output can change. Zero-frame control flushes are accepted.
Prepared DSPFX type changes reuse allocated buffers and reset in place. All 21 types and 42 EQ IDs pass the native host mapping test.

The Rust workspace suite and web production build pass. These are native host-adapter tests; a Main CLAP or VST3 class is still to be built.

Next boundary

The fixed ID ranges for LFOs and control utilities are reserved but not yet wired. A coherent live save cannot read mutable loop PCM concurrently with audio; the save transfer needs its own safe block-boundary protocol. Repeated FX type switch costs also need measurement on an audio device.
