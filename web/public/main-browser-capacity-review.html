What was measured

Actual browser path

Headless Chromium loaded the built AudioWorklet adapter and Wasm from this site. One prepared Main voice bank played 1, 4, or 8 held notes from a deterministic four-second stereo source. The Rust meter confirmed the active voice count in every case.

Measurement boundary

The WebAudio DevTools metric was sampled through the WebAudio protocol every 100 ms after warmup. Its capacity value is a rolling browser estimate, so the table’s p95 is across samples, not individual 128-frame callbacks. The reported output callback buffer was 512 frames at 48 kHz.

This run used Chromium’s headless virtual output. Capacity below 100% is encouraging, but this capture cannot count physical audio-device underruns or prove glitch-free playback on the user’s speakers. A regular-browser/device run and listening check remain open. The older Node/V8 callback timings use a different method and should not be compared as the same statistic.
