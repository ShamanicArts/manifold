What ran through the host

1 · BrowserThe workbench exported Tone Texture JSON with Frequency bound to zero-based slot 41, displayed as slot 42.
2 · VST3The Rust exporter validated that exact JSON and produced a standard .vstpreset.
3 · REAPERREAPER loaded the preset, reported 0.019399 for slot 42, then accepted a normalized value of 0.1.
4 · AudioTwo saved REAPER projects rendered in fresh processes. The dominant tone moved from 330 to 1618 Hz.

Frequency was measured from an 8,192-frame window of the left channel beginning at 0.25 seconds. The peak sample difference between the two full renders was 0.4348. This proves the mapping affects host audio; the earlier VST3 host proof covers native render parity and the original widget gestures.

The native editor now assigns slots too

REAPER read the moved control at normalized 0.645833 and the old slot at 0. The host then set slot 42 to 0.75, making the control +12 semitones. It saved the project and rendered a MIDI note in a fresh REAPER process.

The complete 48,000-frame stereo render matched direct native Rust within 5.96e-8 peak sample error. Three isolated runs returned the same measurements. Steinberg's validator passed 1,074 tests with no failures after the editor change.

An existing DAW envelope follows its slot

REAPER already held a two-point Read-mode envelope at normalized 0.75 on slot 2. An XTEST edit moved Semitones from slot 1 into that occupied slot, moving Waveform to slot 1. During playback the same envelope drove Semitones to +12 without rewriting the automation.

REAPER saved the project and rendered it in a fresh process. All 48,000 stereo frames matched a direct Rust render of the resulting Square-wave voice at +12 semitones within 5.96e-8 peak sample error. Three isolated runs gave the same result.

Control contract and next steps

The VST3 class keeps 128 public parameter IDs. A project only changes which graph control each ID targets. Moving a control to an occupied slot swaps the pair; existing DAW automation on either slot will then reach the new target. The workbench states this beside the assignment controls.

Changing a slot in the native editor currently reloads the graph, which resets active voices and effect tails. Next: test larger projects and other DAWs, then extend the general graph host adapter to CLAP. Windows and macOS VST3 packaging still need validation. The current host proof is Linux REAPER.

Reproduce after building the web and VST3 bundles: node scripts/verify-graph-workspace-browser.mjs, then run python scripts/probe-reaper-graph-host-slot.py, python scripts/probe-reaper-graph-vst3-gui.py --slot-assign, and python scripts/probe-reaper-graph-vst3-gui.py --slot-automation with DISPLAY on a disposable X server and MANIFOLD_ISOLATED_DISPLAY=1.
