A sample region joins the graph.

The editable project can now use either an eight-voice sample instrument or a single retriggerable sample region. Both bind decoded audio to a Rust node ID, keep it in project JSON, and load it before the audio callback begins.

Evidence and limits

Native Rust and direct Wasm output are bit exact for the retriggered region case. Chromium starts the actual AudioWorklet, updates Speed while running, downloads an embedded-source project, reopens it, and starts it again. The existing sample instrument remains separately playable with two source nodes in one graph.

This is a native Rust versus Rust/Wasm comparison. It does not establish C++/JUCE parity for this composed graph. The region has one playhead; it is a different behavior from the polyphonic sample instrument.
