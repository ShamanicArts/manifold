The handoff

1. ParseThe control thread validates browser session v1–v15 and prepares a complete Rust Main instrument.
2. OfferOne pending runtime waits in an atomic slot. A later valid offer replaces it on the control thread.
3. PublishAfter a successful audio block, the audio endpoint swaps Box pointers. The next block uses the new instrument.
4. RetireThe displaced runtime goes into a bounded queue and is destroyed by the control thread.

What was checked

Audible replacementA prepared session with a 0.25-level playing loop replaces silence; a second session changes it to 0.5 on the next boundary.
Failed and superseded importsInvalid JSON preserves the current runtime. If two valid files wait, only the latest reaches audio.
Concurrent threadsA control thread submits a session while the audio thread continues to render. The published generation and retired count are checked.
Cross-platform coreThe previous eight-block native/Wasm Main session comparison remains below 1e-8 maximum sample difference.

The full Rust workspace test suite passes. This is a host boundary, not yet a loadable Main CLAP or VST3 class.
