From behavior studies

The Rust core now powers a JavaScript browser workbench and native Linux CLAP/VST3 plug-ins. A substantial set of original C++/JUCE and Lua behaviors has been reconstructed and tested in isolation and in authored projects. Main's four-layer looper and its wave and Sample voices share one Rust/Wasm audio path. Its original editor has now recorded, saved, reopened, and played both loops and captured Sample notes in REAPER. The full old Manifold project set has not yet been reproduced.

Architecture that is holding up

Rust owns DSP and audio state. The browser AudioWorklet and native host adapters only bridge devices, timed events and bounded control messages. JavaScript owns the workbench; its visual renderer reads analysis and never sets audio timing. Capture buffers, graph memory and resources are prepared before callbacks. Legacy JUCE/Lua remains the behavior and design reference; there is no Lua runtime in v2.

The strongest evidence is local behavior parity and end-to-end browser/REAPER paths. It does not yet prove every old Manifold project, broad host compatibility, physical-device underrun safety, or macOS/Windows packaging.

Current porting checkpoint

The exported Standalone Sample now has a dedicated browser page. Its 472 × 220 shell uses the authored graph, panel, and source dropdown bounds; the old DSP's single dynamic slot maps to one Rust sample instrument and two capture rings. The richer Main rack Sample remains a separate surface. The browser host controls below the plugin page are explicit additions because the exported standalone UI does not author capture and pitch widgets.

The first review proves the browser capture, note, state, and native Graph CLAP/VST3 import. Next are C++ screenshot/audio comparisons, a dedicated native Standalone Sample editor/class, native file replacement, transport quantization, remaining pitch modes, and broader rack slot persistence.

Main's former “Patch” navigation was only a scroll to selector controls, so it is labelled “Routes.” A separate Audio Patch face now switches six existing shells to ports and lets audio cables rewire the prepared Rust/Wasm graph. Version-16 sessions now save and reopen those six-module audio cables in browser and native Rust. A packaged CLAP state probe and VST3 component test retain the cable; browser grid dragging and saved shell placement now work; native editor drag, full shell controls, full port behavior and DAW roundtrip still need work. The Main page also has a hardware MIDI input bar and a saved rack layout review with explicit permission and device choice. Read the specific core readiness gates.
