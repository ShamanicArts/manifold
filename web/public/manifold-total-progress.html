Architecture that is holding up

Rust owns DSP and audio state. The browser AudioWorklet and native host adapters only bridge devices, timed events and bounded control messages. JavaScript owns the workbench; its visual renderer reads analysis and never sets audio timing. Capture buffers, graph memory and resources are prepared before callbacks. Legacy JUCE/Lua remains the behavior and design reference; there is no Lua runtime in v2.

The strongest evidence is local behavior parity and end-to-end browser/REAPER paths. It does not yet prove every old Manifold project, broad host compatibility, physical-device underrun safety, or macOS/Windows packaging.

Current porting checkpoint

Port the exported Standalone Sample and the shared Main rack Sample as two related surfaces. The exported 472 × 220 shell authors a graph panel, a control panel, and an Audio Input/Sidechain dropdown; its DSP creates one dynamic sample slot. The richer Main rack component authors capture, pitch, root, unison, detune, spread, crossfade, and output widgets. The standalone UI reuses the rack behavior script, but those extra widgets are absent from its authored layout. The current v2 sample study is a generic workbench view, so neither historical surface is visually proven yet.

The first review will compare each authored widget layout with a running browser surface and connect supported controls to the existing Rust/Wasm sample engine. It will label missing DSP behavior explicitly. Then carry native live file replacement, transport quantization, remaining pitch modes, and any broader rack slot persistence through portable project state and host adapters.
