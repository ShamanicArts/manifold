The editor request becomes a bounded frame count on the host control path. The audio callback publishes tempo and meter as an atomic snapshot, freezes prepared Rust graph history, and copies at most 2,048 stereo frames per service. The saved project records captureWindowMode: bars, 0.5 bars, 90 BPM, 3/4, and the effective one-second window.

Each REAPER project was saved, reopened in a fresh process, and rendered for six seconds. Its first second matched the direct native Rust render at the stated peak sample error. The host test also checks the bar, tempo, meter, and effective seconds fields in saved state.

Browser and Wasm agreement

The browser project reader now accepts the saved meter fields, shows them beside the compact graph controls, and sends them to the Rust/Wasm timing helper. In the browser workbench, a 0.1-bar window at 120 BPM in 3/4 captured 7,200 frames at 48 kHz; the bundle saved and reopened with the same meter and effective 0.15-second window. Projects without an explicit meter continue to use 4/4.

What comes next

Bar capture currently snapshots the host tempo and meter when the user requests it. Tempo ramps within a retrospective window and the old free-mode start/stop offsets still need a defined host behavior. The next study will expose ring write positions and carry those offsets through the same portable project path.
