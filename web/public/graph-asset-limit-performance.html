The deadline is 2.667 ms for 128 frames and 21.333 ms for 1,024 frames at 48 kHz. These values are the median p95 across three release-build runs; the largest observed block is the maximum across those runs. Each 128-frame run timed 4,096 blocks; each 1,024-frame run timed 512 blocks. Output remained audible at the end of every case.

What was measured

AMD Ryzen 9 3900X, 48 kHz, release build. The harness decoded a 44,742,408-byte browser-format JSON project and prepared its four PCM assets before timing. Median parse time was about 53 ms and graph preparation about 4 ms; both occur outside the audio callback. After inserting the note-on events and warming 64 blocks, it timed only NativeProcessor::process with preallocated input and output buffers.

The three raw runs and a shorter-source comparison are in the measurement JSON. The shorter sources loop during the run, so that comparison does not isolate the effect of PCM size on callback time.

Scope of the result

This is an offline native processor measurement. It excludes DAW scheduling, editor activity during playback, live MIDI event insertion, operating-system audio callbacks, and physical device underruns. The host import proof establishes saved-project audio parity separately; real-host callback timing remains a follow-up.

Reproduce the fixture with python scripts/probe-reaper-graph-vst3-gui.py --four-sample-import --emit-project /tmp/manifold-four-source-bench.json, then run cargo run --release -p manifold-native --example bench_graph_callback -- /tmp/manifold-four-source-bench.json.
