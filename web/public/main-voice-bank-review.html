How a note travels

timed MIDI → original eight-slot policy → per-voice note pitch + FM/Sync → oscillator + shared-sample playhead → per-voice vocoder → wave/sample blend → sample-clock ADSR → stereo sum

Ownership

An idle slot wins first; otherwise the quietest releasing slot, then the oldest active slot. Duplicate notes occupy separate slots and release together, following the original UI trace.

Preparation

Eight playheads share one decoded stereo buffer. Scratch audio, FFT storage, and envelopes are prepared before audio rendering. Note events only reset existing state.

Control

Wave shape, blend, root and keytrack, sample pitch engine, FM/Sync, and ADSR can be auditioned in the workbench. MIDI event offsets enter the Rust graph.

Limits and next work

This is the Main base wave/sample branch. Add, Morph, Ring, linked branch depth, full project state, and native plug-in packaging have not been assembled into this voice bank. The old Main UI updates its envelope at UI cadence; this bank intentionally uses a sample-clock ADSR and therefore does not claim full old-project audio parity.

The next pass will connect the remaining source families to each voice, compare assembled output with selected original C++ routes, and measure sustained polyphony cost in the browser. Hardware MIDI permissions are unavailable in BB’s embedded browser; the on-screen keyboard works.
