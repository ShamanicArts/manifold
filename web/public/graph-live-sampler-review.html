Manifold v2 / live sampler checkpoint / 27 September 2026

Record a take. Keep playing.

A loop capture in the editable graph can now supply a running sample instrument. Notes already sounding finish on their original PCM; later notes use the captured take. The project bundle carries that take into the next session.

Open the graph workspacePrevious Main checkpoint

One graph, two time scales

External audio→Loop capture · 2 s→Mix→Output
MIDI→8-voice sample instrument→Mix
Stopped capture→ publish between blocks →Next-note source

The graph is compiled in Rust before audio starts. A stopped take is copied from the prepared ring when you press Use stopped take. Source adoption does not rebuild the graph or reset held notes.

Try it in the browser

01

Load

Choose “Replace graph with live sampler study.” Leave Test oscillator selected, or choose Microphone to record your own input.

02

Record

Start audio. Set Loop capture 6 → Record to Recording, wait briefly, then set it to Stopped.

03

Publish

Press “Use stopped take” under Sample instrument 5. Play the keyboard before and after to hear the source handoff.

04

Reopen

Download the graph project. Reopen it after stopping audio; the take is embedded as the instrument source.

What is proven

139Rust core tests passing, including held-note and graph capture handoff
512frames captured in the deterministic Wasm worklet test
0page errors in the Chromium save/reopen scenario

Rust rejects empty or still-recording takes. The Wasm worklet test confirms that a held note keeps its old source, a new note reads the captured source, and release of the old note leaves the new note sounding. Chromium records the test oscillator, publishes it, saves the embedded PCM, reopens the graph, and starts audio again.

This is a stopped-take publication from the graph’s external audio input. A dedicated host sidechain bus and continuous source replacement while a ring is still recording remain future contracts. Publication allocates and copies on the worklet message path between render calls; the render loop itself uses prepared storage.
