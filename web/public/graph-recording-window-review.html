What changes in the engine

stereo input→bounded ring→staged frozen window→new-note source

Rust fixes the ring start and length when you request the window, then copies a bounded slice before each following render block writes. After the window is frozen, the browser receives it in small chunks for project save. Rust moves the staged buffer into the instrument; held notes keep their previous source. The older “Use stopped take” control still requires recording to stop.

The direct worklet check exercises publication during recording, continued capture, held-note source continuity, new-note adoption, the stopped-take gate, and the sidechain input. The Rust ring test checks frozen ordering after wrap and cancellation on recording restart. The Chromium graph test publishes while recording and saves the asset.

Publication cost

The first one-shot worklet handler copied and published a full two-second stereo window in 1.83 ms at p95. In a synthetic 48 kHz Node run of the staged Wasm path, 30 publications took 47 render blocks each to freeze the window. Staged render calls measured 0.0138 ms p95 versus 0.0080 ms baseline. The begin, chunk, and final commit handlers measured 0.38, 0.12, and 0.09 ms p95 respectively. A 128-frame quantum is 2.67 ms. This probe excludes browser message transfer, the physical audio device, and underruns; it is a cost signal, not a glitch-free guarantee.

This is a user-triggered snapshot, not an always-running retrospective capture service. The two-second study is bounded; its sample data is saved with the graph project. Frequent or automatic publication still needs device timing and underrun measurement.
