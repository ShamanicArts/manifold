Slot lifecycle

ActionHost behavior
Address a control or routeEach slot has a fixed 16-ID stride from 512. Local IDs 0–4 set LFO controls; 5–10 set route fields.
Activate or remove slots 2–4Local ID 11 toggles that slot. Slot 1 is always present. Valid automation for an absent slot is held without running that LFO and applies when the slot becomes active.
Remove and recreateDSP and route state reset. The host value bank clears old slot edits; the next save uses the original default LFO face until new edits arrive.
Save and reopenThe native save emits the browser's sparse rack.lfos array. The browser opens and saves both the current and upgraded v3 examples with identical loop/sample PCM and the native LFO 2 controls.

Native tests also activate all four slots, reject a malformed queue before slot activation, verify a removed slot disappears from the saved array, and check that a recreated slot does not inherit stale route values. They now check that new host edits sent while a slot is absent apply on activation.

Next boundary

The assembled Main runtime and its stable host ID bank now need a loadable Main CLAP class and VST3 processor/controller, followed by external host save/reopen and audio checks. Repeated FX type switching still needs a callback cost measurement on a real audio device.
