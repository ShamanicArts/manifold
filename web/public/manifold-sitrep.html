01

The shape of the new system

Interaction

JavaScript workbench

Compact controls, keyboard, file loading, project selection, plots, and review cases. Three.js and WebGPU remain the direction for richer rendering where needed.

Real-time bridge

AudioWorklet

Passes timed events and bounded parameter or asset updates into the audio thread; publishes small meter snapshots back out.

Sound & state

Rust core → Wasm

Typed audio, CV, and MIDI graph; DSP kernels; sample-accurate event handling. The same core can run natively for comparison and future hosts.

Analysis and file preparation can run away from the audio callback. Rendering stays separate from sound processing. Legacy Lua is a behavior reference, not a v2 runtime dependency.

02

What is built

Playable

Instruments and source audio

Voice synth and MIDI transforms, sample region and sample instrument, loop capture, granulator, and file analysis. On-screen instruments work without hardware MIDI permission.

Playable

Effects and routing

Filter, dynamics, EQ, delay, modulation, distortion, spatial, pitch, shimmer, stutter, reverse, formant, resonator, a manual 32-partial Sine bank, and an FX slot with several audited switch behaviors.

Composable

Graph and control signals

Typed audio/CV/MIDI routes, LFO and slew, a CV rack slice, envelope ducking, timed MIDI events, bounded meters, and selected v2 JSON patch/state roundtrips.

Still expanding

Project reconstruction

Existing views are proof points, not a completed port of Manifold’s old project library. Full sample synth branches, shared project state, host packaging, and broad preset migration remain ahead.

03

What the evidence says

Kernel behavior

Checked-in comparison captures pair old C++ outputs with Rust/Wasm for isolated nodes, and native Rust with Rust/Wasm for new compositions. The workbench exposes waveform differences and case-level results.

Latest completed slice

A first Main sample blend study connects file-backed stereo playback, worker-prepared Add/Morph targets, Sine bank, and a two-bus mixer. Four native Rust graph renders match direct Rust/Wasm sample for sample. Inspect the branch review.

Browser path

The same Rust core compiles to Wasm and runs inside an AudioWorklet. Playable views, controlled offline runs, and downloadable project slices exercise this path on the served site.

Scope of claim

The numbers establish many local behaviors and some small compositions. They do not establish parity for the complete old plug-in, its full Lua project graph, every preset, or a native plug-in host.

Hardware MIDI access in BB’s embedded browser is currently constrained by host permissions. Use the on-screen keyboard here; hardware permission can be tested in a regular browser later.

In flight, then next

Done · partial analysis

Source-derived frames are reviewable

The Rust/Wasm worker extracts bounded temporal frames with region and confidence metadata. Four C++ fixtures match; selected frames play through the Sine bank. Legacy pitch detection is still separate.

Done · Add and Morph targets

Prepare and audition source-based spectra

Wave recipes, temporal interpolation, Add, and Morph match 17 C++ cases. The browser exposes a playable prepared target, with fixed-size publication between audio blocks.

Done · first Main branch study

One source feeds playback and prepared Add/Morph targets. Separate sample and bank gains allow branch audition, with four native-versus-Wasm graph comparisons.
