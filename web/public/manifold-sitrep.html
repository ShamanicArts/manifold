Manifold v2 / project sitrep / checkpoint 118

A portable sound engine is taking shape.

The old JUCE and Lua project is being rebuilt as a Rust DSP core with a JavaScript browser workbench. The workbench is already useful for playing, inspecting, and comparing individual behaviors; the full legacy projects are still being assembled.

01

The shape of the new system

Interaction

JavaScript workbench

Compact controls, keyboard, file loading, project selection, plots, and review cases. Three.js and WebGPU remain the direction for richer rendering where needed.

Real-time bridge

AudioWorklet

Passes timed events and bounded parameter or asset updates into the audio thread; publishes small meter snapshots back out.

Sound & state

Rust core → Wasm

Typed audio, CV, and MIDI graph; DSP kernels; sample-accurate event handling. The same core can run natively for comparison and future hosts.

Analysis and file preparation can run away from the audio callback. Rendering stays separate from sound processing. Legacy Lua is a behavior reference, not a v2 runtime dependency.

02

What is built

Playable

Instruments and source audio

Voice synth and MIDI transforms, sample region and sample instrument, loop capture, granulator, and file analysis. On-screen instruments work without hardware MIDI permission.

Playable

Effects and routing

Filter, dynamics, EQ, delay, modulation, distortion, spatial, pitch, shimmer, stutter, reverse, formant, resonator, a manual 32-partial Sine bank, and an FX slot with several audited switch behaviors.

Composable

Graph and control signals

Typed audio/CV/MIDI routes, LFO and slew, a CV rack slice, envelope ducking, timed MIDI events, bounded meters, and selected v2 JSON patch/state roundtrips.

Still expanding

Project reconstruction

Existing views are proof points, not a completed port of Manifold’s old project library. Full sample synth mode routing, shared project state, host packaging, and broad preset migration remain ahead.

03

What the evidence says

Kernel behavior

Checked-in comparison captures pair old C++ outputs with Rust/Wasm for isolated nodes, and native Rust with Rust/Wasm for new compositions. The workbench exposes waveform differences and case-level results.

Latest completed slice

The playable Main study runs Normal, FM, and Sync motion in Rust; its 34 native Rust ↔ Wasm audio cases include seven exact directional captures. The next isolated Rust pitch map matches 14 original Lua scenarios, with at most 0.0001163 Hz wave-frequency difference. Its note/root controls are not yet wired into the graph. Version-10 state opens all nine earlier formats. Inspect the playable branch or inspect the pitch-map trace.

Browser path

The same Rust core compiles to Wasm and runs inside an AudioWorklet. Playable views, controlled offline runs, and downloadable project slices exercise this path on the served site.

Scope of claim

The numbers establish many local behaviors and some small compositions. They do not establish parity for the complete old plug-in, its full Lua project graph, every preset, or a native plug-in host.

Hardware MIDI access in BB’s embedded browser is currently constrained by host permissions. Use the on-screen keyboard here; hardware permission can be tested in a regular browser later.
04

In flight, then next

Done · partial analysis

Source-derived frames are reviewable

The Rust/Wasm worker extracts bounded temporal frames with region and confidence metadata. Four C++ fixtures match; selected frames play through the Sine bank. Legacy pitch detection is still separate.

Done · Add and Morph targets

Prepare and audition source-based spectra

Wave recipes, temporal interpolation, Add, and Morph match 17 C++ cases. The browser exposes a playable prepared target, with fixed-size publication between audio blocks.

Done · first Main branch study

Sample and prepared bank share one output

One source feeds playback and prepared Add/Morph targets. Separate sample and bank gains allow branch audition, with four native-versus-Wasm graph comparisons.

Done · Main blend state

Save and reopen a source-backed study

Version-10 JSON holds 28 graph controls, target settings, and either the built-in source choice or bounded stereo PCM from a file. Both bank targets are rebuilt in the worker when reopened.

Done · phase vocoder

Port both modes and expose the stereo correction

Nine C++ captures and a playable workbench reveal where the Rust stereo clock intentionally differs. The sample branch now uses the vocoder in the Main study.

Done · additive phrase contour

Let the raw sample shape Add/Morph loudness

A typed follower drives a prepared phrase gain node. The original C++ detector matches the Wasm graph; two new native/Wasm captures show full and half shaping. Earlier state files open with a neutral contour.

Done · wave/sample base

Crossfade oscillator and processed sample

Wave shape, pitch, level, and base position are playable. Three new native/Wasm captures match exactly; the AudioWorklet reaches wave only, sample only, and a moving centre blend.

Done · dual additive sources

Crossfade prepared wave and source spectra

The worker publishes two bounded targets; the AudioWorklet holds two banks. Wave-only and midpoint additive captures match native Rust exactly.

Done · linked branch depth

Move base and Add gains together

One Rust parameter sets complementary gain targets with the mixer's existing smoothing. Depth 0, midpoint, and 1 native/Wasm captures match exactly; independent audition gains can be restored.

Done · Main sample gain stages

Follow the old voice output path

Sample stage gain, branch mixer, and four-bus voice mixer reproduce three compiled C++ sample-only amplitude cases exactly. The workbench saves the new control in version-7 state.

Done · linked voice amplitude

Move all three source families together

A bounded parameter batch sets the oscillator, sample gain, and both prepared banks from one control. Five new native/Wasm cases and live worklet checks cover wave, sample, and Add paths. Older state files open with linking off.

Done · sample-driven oscillator sync

Reset wave phase on raw crossings

The Rust oscillator has an optional audio sync input, matching the compiled C++ node exactly. Two Main graph cases and a live worklet toggle exercise the route.

Done · FM and Sync motion

Move wave pitch and sample playback in Rust

At each audio block, FM changes both source rates; Sync chooses replay or retrigger and gates hard sync by blend position. Seven new audio captures match native Rust and Wasm exactly. A separate original Lua trace checks 13 control blocks.

Done · isolated Main pitch map

Trace note and sample pitch decisions

Fourteen original Lua scenarios match a pure Rust mapping for wave frequency, desired sample ratio, sample speed, and vocoder pitch/mix. The mapping is ready for live graph integration.

Now · full sample project

Bind pitch and build note behavior

Wire the checked Main pitch map to the authored graph, then add per-note gate and allocation. Compare assembled old Main voice output. Ring mode and Add/Morph routing remain. An ADSR gate would be a v2 redesign: old Main references one but does not construct it.

Later · product surface

Harden the shared project model and hosts

Broaden state and preset handling, measure callback budgets in the browser, and package non-browser hosts against the same Rust engine.
