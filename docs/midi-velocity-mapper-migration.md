# Main rack Velocity Mapper migration boundary

The old `velocity_mapper_runtime.lua` shapes the amplitude fields of a voice bundle. It normalizes amplitude to 0–1, blends the original with a selected curve using Amount, then adds Offset multiplied by Amount and clamps the result. Linear leaves the normalized value unchanged; Soft uses `n²(3−2n)` and Hard uses `n²`. The two legacy rack tests pass, including a Hard curve that maps amplitude 0.5 to 0.25.

The old `export_midi_effects.velocity_mapper` uses the generic voice transform adapter. That adapter reads the processed voice's pitch but sends the held note's original MIDI velocity. The [legacy MIDI probe](../tools/legacy-midi-velocity-mapper.lua) shows note 64 at velocity 64 staying at velocity 64 after switching to Hard. That export does not expose the rack's audible amplitude transformation to a downstream MIDI instrument.

V2 deliberately applies the rack curve to MIDI velocity divided by 127, then rounds back to a MIDI integer. Thus the same note changes from velocity 64 to 32 when Hard is selected. A zero result suppresses the note-on while retaining the held input; a later control change can make it sound. Changing a parameter sends note offs for all sounding held notes before the recalculated note ons, following the old adapter's retrigger order. [The event comparison](../artifacts/reviews/checkpoint-101-midi-velocity-mapper-events.json) makes the old export and v2 difference explicit.

[`MidiVelocityMapper`](../crates/manifold-core/src/midi_velocity_mapper.rs) uses the same fixed eight-slot router as the other MIDI effects. The router now accepts a mapped note and velocity without allocating, while its note-only interface keeps prior effects unchanged. The [browser workbench](../projects/midi-velocity-mapper/project.json) runs `MidiInput → MidiVelocityMapper → VoiceSynth`, exposes Amount, Curve, and Offset, and displays the bounded Rust output trace. Its on-screen keyboard works without Web MIDI permission; hardware input requires a browser view that allows `requestMIDIAccess()`.

The native Rust fixture holds two notes under Hard while Offset rises. Direct Wasm, the actual AudioWorklet adapter, and the workbench comparison renderer reproduce all 8,192 stereo frames exactly. See [checkpoint 101](../artifacts/reviews/checkpoint-101.md). This is a Rust audio reference plus a legacy Lua behavior audit, not a C++ audio capture.
