# Stutter migration boundary

The original `dsp/core/nodes/StutterNode.cpp` writes stereo input into an eight-second ring. At each beat-length boundary it consumes one seeded JUCE random value, checks one bit of an eight-step pattern, and either plays a reversed fragment or passes input through. Active fragments use a gate, pitch slowdown, and a one-pole filter decay. Rust graph kind 48 ports the processing order, `juce::Random` 48-bit stream seeded with `12345`, per-sample 10 ms smoothing, and independent stereo filter state. The [workbench](../projects/stutter/project.json) exposes beat length, gate, filter and pitch decay, probability, eight-bit pattern mask, tempo, and wet mix.

The Rust ring is allocated before audio starts. Generation stamps make a type switch clear its audible history in constant time without clearing eight seconds of memory inside the callback. The random seed persists across resets, matching the original node's `reset()` behavior. Segment length is recalculated on every sample, as in C++, even while a segment is active.

Eight checked-in C++ captures cover default seeded behavior, always-on probability, probability sweep, alternating pattern, gate/filter decay, pitch/tempo, wet mix, and 64-frame blocks with length changes. All eight show **Match** against Rust/Wasm with zero maximum sample difference in these cases. A separate combined length and mix sweep measured a `6.02e-4` one-sample maximum difference near a moving segment boundary; that joint transition remains a numerical parity edge. The checked-in cases separately exercise both controls.

Standalone FX type 20 maps normalized `p/0` to length `0.125…8` beats, `p/1` to gate, `p/2` to probability, and `p/3` to filter decay; `p/4` is unused. The old Lua slot leaves pitch decay at `0.2`, pattern at all eight steps on, tempo at `120 BPM`, and internal mix fully wet. Four new slot cases compare native Rust with Rust/Wasm. Old project routing and preset roundtrips remain separate work.
