# Prepared patch editing contract

The [graph workspace](../web/public/graph-workspace-review.html) now provides a separate stopped-audio topology editor. It can add or remove eight palette node kinds, connect typed Audio and CV ports, change initial parameters, and download/reopen a `manifold.project` version-1 document. Its JavaScript validator checks IDs, fixed input/output nodes, port type and occupancy, cycles, parameter ranges, and exact document shape before replacing session state. Rust/Wasm compilation on the next audio start is the final validator. This differs from the live prepared-route mechanism below: topology edits reset kernel state when playback restarts. The graph workspace has its own project ID and does not import the Main fixed-graph bundle or legacy Lua files.

Its node parameter fields also work while audio is running. The browser validates a value, sends a request to the AudioWorklet, and waits for the Rust setter's acknowledgement before changing project state. A rejected update restores the previous value. The non-patchable graph compiler prunes unreachable nodes; their deferred starting parameters stay in the saved document but are not applied, and live edits to those parked nodes are rejected until a stopped route edit makes them reachable. Pending requests are rejected when audio stops. See the [live controls review](../web/public/graph-live-controls-review.html).

The CV rack project declares eight editable control input ports. Each port offers a small list of earlier control-output nodes plus an unconnected choice. The source lists are typed and ordered so the offered routes cannot form a cycle. Audio connections stay fixed in this slice. Rust graph compilation validates port type, occupancy, IDs, and topology on each start; live route changes are also checked by Rust for prepared source and target IDs, matching signal kinds, and source-before-target order.

The Ring Modulator project applies the same prepared-route contract to its optional Audio input. The selector chooses the internal oscillator (no input edge) or a copy of the live stereo input on port 1. A route change is acknowledged by the AudioWorklet before the browser updates its session graph. With the external input connected, the internal oscillator phase freezes; disconnecting resumes that phase. This is the normal v2 optional-input behavior; the separate old Standalone FX host comparison preserves the old silent-input-view quirk. Ring's route and five public controls use the same versioned JSON patch shape as the CV rack, with project ID validation and a distinct filename.

The browser copies the authored signal description into session memory. Changing a dropdown while audio runs sends one route request to the AudioWorklet. Rust replaces one source index in the prepared `ExecutionPlan` and recomputes reachability in a reverse pass, with no allocation or plan rebuild. The browser records the new connection only after the worklet acknowledges it; on rejection or timeout, the selector returns to its prior value. A stopped edit changes only the session description and is compiled on the next start.

All CV rack kernels and buffers are allocated at start, including nodes currently disconnected from Output. Nodes unreachable from Output are parked: `process()` skips them and their state freezes. Reconnecting one resumes its retained LFO phase, sample/hold latch and trigger state, or other kernel state. The stage meter marks parked nodes as inactive and holds their last active reading. The oscillator and gain path continue while CV routes change. A full stop/start still creates fresh state: LFO phase, sample/hold latch, gain smoother, oscillator phase, and meters reset to initial conditions. The browser retains authored parameter slider values and replays them when the new graph is ready.

The CV rack workbench can download and reopen a versioned JSON patch containing all eight editable routes and ten public control values. Ring Modulator uses that format for one Audio route and five public controls. Import validates the exact project ID, schema version, one route per declared port, each source against that port's choices, and every parameter value before changing session state. Import is available only while audio is stopped; starting the graph compiles the restored Rust graph. The [checkpoint 70 example](../artifacts/reviews/checkpoint-70-patch.json) is a file generated by the workbench. This is a v2 patch document, not a legacy Lua patch or a native plug-in preset. Edits persist while switching workbench views in one page session; download and reopen preserve them across reloads.

The first live check disconnected both `CvMix` inputs without stopping audio. Its offset alone produced 0.10 mixed CV and 0.65 effective gain from base 0.60 with depth 0.50. Reconnecting the source LFO to mix input 1 produced changing CV values on the running graph. All 29 offered source choices were accepted by the worklet verifier; an audio source on a CV port was rejected. This verifies that the selector changes the Rust signal path, rather than only redrawing the browser diagram.

This mechanism edits connections among a fixed set of prepared nodes. Adding or removing nodes, changing their kinds, or choosing a route that needs a new topological order still requires a new plan. A general live topology replacement needs preparation away from the callback, block-boundary publication, retirement of the old plan, and explicit state migration. The [Web Audio specification](https://www.w3.org/TR/webaudio/) places AudioWorklet code on the rendering thread, so preparing a whole replacement graph in its message handler would risk interrupting audio.
