# Timed note event contract

The voice foundation introduces `TimedEvent { offset, node, kind }` in Rust. `offset` is a zero-based frame position **inside the next block**. Events are ordered by offset, with insertion order preserved for events at the same frame. The graph validates all offsets and destinations before processing, renders each span up to an event, applies the event to its target node, then renders the remaining span. This makes an event at frame 127 distinct from one at frame 128 across 128-frame blocks.

The first event kinds are note on, note off, and all notes off. A zero-velocity note on acts as note off. The voice node has eight fixed slots, retriggers the same channel and note, uses a free slot when available, and otherwise steals the oldest active slot. Note off enters release from any envelope stage. This fixes the old `MidiVoiceNode` scalar path's attack-stage note-off behavior as an intentional redesign; these voice cases are compared with native Rust, not presented as C++ parity.

The Wasm ABI reserves 256 events in each prepared engine. `manifold_event_push` appends to the queue without allocating; `manifold_process` consumes and clears it. Browser keyboard and device messages currently arrive at offset zero of the next callback block. Offline fixtures supply arbitrary offsets to verify the timing contract. The on-screen keyboard uses channel 15; optional Web MIDI input preserves each device message's channel, note, and velocity. The **Request MIDI access** button calls `navigator.requestMIDIAccess({ sysex: false })` after user interaction, handles device hotplug, and reports denied or unavailable access. The in-app browser may block permission. The Voice view keeps six recent note events with source, channel, note, and velocity; hardware messages received while audio is stopped are labeled *received only*. The event list is a main-thread diagnostic and does not drive DSP. Accurate scheduling of external MIDI timestamps remains to be implemented. No Lua is imported.

The voice node is a playable baseline with sine, saw, square, triangle, ADSR, level, and stereo centre output. Its oscillator and envelope are integrated into one voice kernel for now. A separate standard-waveform Oscillator is now patchable in the graph. MidiInput, additive oscillator modes, and modulation nodes, along with the fuller authored MIDI Synth project and its effects, remain to be ported or redesigned.

The separate patchable `ADSREnvelope` currently uses a gate parameter, independent of note events. The browser gate button sends that parameter to the next worklet block. Its early-release behavior deliberately differs from the old C++ scalar node, which may wait until sustain after a gate-off during attack or decay.

The browser MIDI adapter currently handles note on, note off, and zero-velocity note on. It releases held notes when a device disconnects or listening stops and keeps simultaneous notes from multiple devices active until their last source releases them. Sustain pedal and other controller messages are not mapped yet. See the [Web MIDI API specification](https://www.w3.org/TR/webmidi/) for the browser permission and input event contract.
