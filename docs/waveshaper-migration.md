# WaveShaper migration boundary

The original `dsp/core/nodes/WaveShaperNode.cpp` is the Standalone FX type 2 processor. It is distinct from the old `DistortionNode` and from the authored v2 FX chain. The Rust `WaveShaper` runs as graph kind 37 with eight parameter IDs: curve, drive dB, output dB, pre-filter Hz, post-filter Hz, bias, mix, and coefficient mode. The [workbench project](../projects/waveshaper/project.json) exposes all eight. The [Standalone FX slot](../projects/standalone-fx-slice/project.json) maps four normalized controls to drive, curve, output, and bias using the old Lua definitions; the fifth is unused.

The scalar C++ processor smooths drive, output, bias, and mix over 10 ms, and filter frequencies over 50 ms. It processes the left channel before the right, so a shared smoothing state is further advanced for right-channel samples after a parameter change. The Rust port preserves that order for comparison. Curve changes take effect at the next sample; filter states are per channel. The C++ filter coefficients are updated only while the smoothed frequency differs from its target by more than 0.1 Hz. The Rust port preserves this threshold.

A real REAPER VST3 [audio render comparison](../web/public/standalone-fx-reaper-audio-proof.html) makes this block partition effect visible. The 48 kHz, one-second WaveShaper render matches a 1,024-frame native Rust reference throughout to the 24-bit WAV quantization limit (`5.96e-8` peak difference). Rendering the same project in 512-frame native blocks changes the initial response by up to `0.0164`, then converges. This is inherited channel-first smoothing behavior, not evidence of a different DSP implementation in the VST3 adapter. A frame-major smoothing redesign would change old-project output and should be reviewed as an explicit behavior change.

The old 1×/2×/4× setting allocates buffers during prepare, but the scalar processing branches are algebraically identical and never upsample or downsample the signal. The setting only divides the pre/post cutoff used for coefficient calculation. The Rust port preserves that audible behavior without allocating unused buffers. The browser labels it **Legacy coefficient mode** to avoid claiming actual oversampling or alias suppression. A future quality redesign could add real oversampling, but it would intentionally diverge from these golden samples.

Eleven C++ fixtures cover all seven curves, curve switching, filter sweeps, mix and coefficient mode, stereo input, and short blocks. The original checkout is read only; [the capture tool](../tools/legacy-waveshaper-reference.cpp) invokes it from v2. Four further native Rust fixtures cover Standalone FX type 2 controls and switching. This slice does not claim project-level legacy preset or gain/mixer envelope parity.
