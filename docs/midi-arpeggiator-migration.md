# Main rack Arpeggiator migration boundary

The old Main rack `arp_runtime.lua` sorts held pitches, expands them through one to four octaves, and steps at 0.25–20 Hz. It supports up, down, ping-pong, and random traversal; gate length is 0.05–1 of the step period. A 30 ms capture window lets a chord entered across callbacks join one initial sequence. Hold latches notes until turned off. The legacy rack's three tests pass, including capture-window and release behavior. V2 also captures keys already down when Hold is enabled.

The old `export_midi_effects.arp` adapter observes voice gates and step stamps after each Lua `process(dt)` call. It emits note offs and ons in output-lane order, including retriggers of repeated steps. On the [128-frame legacy probe](../tools/legacy-midi-arpeggiator.lua), a C4/E4 chord produces the first C4 on, C4 off, and E4 on in callbacks ending at frames 1536, 5248, and 7552. V2's [event comparison](../artifacts/reviews/checkpoint-102-midi-arpeggiator-events.json) places those events at exact frames 1440, 5040, and 7440. The 96-, 208-, and 112-frame differences come from the old callback clock and gate-close timing. The note order is preserved; callback timing is an intentional redesign.

[`MidiArpeggiator`](../crates/manifold-core/src/midi_arpeggiator.rs) owns fixed arrays for eight held notes, eight output lanes, and at most 32 expanded sequence entries. The graph render loop advances to the earliest incoming event or internal arp deadline, renders up to that frame, then routes note events before rendering onward. The same scheduler handles calls with no new input, so a held chord continues to step. A deadline exactly at a block boundary is routed at offset zero of the following block. All notes off clears pending notes and stops sounding lanes at its requested frame. The scheduler uses preallocated MIDI routing and trace buffers.

V2 uses a fixed seeded xorshift sequence for Random so native and Wasm patches can reproduce it. The old Lua `math.random` sequence has no stable seed in the rack. V2 also retains the original channel and velocity for latched notes after key release; the old export can fall back to channel 1 and velocity 100 after its source slot disappears. These are explicit behavior choices to keep held MIDI notes attached to their source.

The [browser project](../projects/midi-arpeggiator/project.json) routes `MidiInput → MidiArpeggiator → VoiceSynth`, with rate, mode, octave, gate, and Hold controls. Incoming notes and bounded Rust output events are visible separately. The on-screen keyboard works without hardware MIDI permission in the embedded browser. Four native Rust audio cases cover capture and all-notes-off, held ping-pong and octave expansion, down mode with short gates, and seeded random mode. Direct Wasm, the actual AudioWorklet adapter, and the workbench comparison renderer match all 32,768 stereo frames per case exactly. See [checkpoint 102](../artifacts/reviews/checkpoint-102.md). These cases establish v2 cross-target behavior; no C++ audio parity is claimed for the Lua arpeggiator.
