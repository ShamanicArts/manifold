# Main rack document, first control-side contract

The authored [rack catalog](../projects/main-looper/rack.json) records the legacy Main default's six active modules and seven voice/audio connections. It preserves original instance and port names such as `oscillator`, `fx1`, `__midiInput`, and `__rackOutput`. `source` is the v2 display/type name for the old `oscillator` instance. Placeholder modules are not included because the current v2 Main page does not instantiate their behavior. The original `rack_midisynth_specs.lua` and `rack_layout.lua` in the read-only checkout define the reference identities, grid, and edges.

Each module instance has a stable **string ID** for authored state and a separate stable **numeric node ID** reserved for the DSP graph and host bindings. Row, column, width and height use the original five-column, 236 × 220 cell grid. Connections name source and target instance/port IDs. Port kind is derived from the catalog; `voice`, `audio`, `cv`, and `gate` are separate. The original Lua code described several of these as generic `control`, but voice bundles and scalar modulation must remain distinct in the new engine.

The catalog now includes the physical sockets on the default ADSR, Source, Filter, FX1, FX2, EQ and LFO modules, plus the Filter Cutoff/Resonance and FX Mix parameter sockets needed for the first control route. Other patchable parameter rows are not enumerated yet. `fx1` and `fx2` are separate catalog types because the original FX1 has an auxiliary `recv` socket and a `2×2` size that FX2 does not. The compiler rejects auxiliary and unimplemented ports explicitly.

The [browser validator](../web/src/state/rack-document.js) accepts version 1 documents, rejects duplicate IDs, layout collisions, absent/reversed/mismatched ports, occupied inputs, and cycles, then returns a detached normalized value. Move, resize, add, remove, connect, replace and disconnect functions are immutable. Replacement of an occupied input validates the final document as one transaction, so a failed wire drag leaves the prior state intact. The [tests](../web/src/state/rack-document.test.js) exercise the authored default and those failure cases.

The first [audio compiler](../web/src/state/main-rack-graph.js) translates the default into the existing portable Graph runtime: MIDI input → Main voice bank → SVF → two legacy FX slots → EQ → output. ADSR is a performance/parameter face for the envelope already owned by the Main voice bank; the compiler requires its original voice route and rejects rewiring it. A deterministic [generated Graph project](../projects/main-looper/default-rack-graph.json) is accepted by the native project reader and by the Wasm worklet. The [signal verifier](../scripts/verify-main-rack-graph-wasm.mjs) shows that bypassing a low cutoff Filter by changing the authored audio edge raises a held note's energy; native and Wasm agree within 0.01% on both rendered conditions. Native save preserves parameters belonging to a disconnected Filter, and reconnecting it restores the filtered output.

The catalog now distinguishes Filter's `env` control input from its patchable `cutoff` and `resonance` parameter sockets, as in the original Lua spec and patchbay generator. The [first CV rack](../projects/main-looper/lfo-filter-rack.json) wires LFO `out` to Filter `cutoff`. It compiles to a nine-node Graph project with a sample-rate control connection. The [CV verifier](../scripts/verify-main-rack-cv-wasm.mjs) measured an 8.84× output-energy change with the wire attached; native and Wasm agree within 0.01%. Native save/reopen keeps the edge. The [browser import check](../scripts/verify-main-rack-graph-browser.mjs) opens both projects and starts audio in isolated, muted Chromium. This earlier exposed and fixed a Graph host startup bug: its standalone FX control lookup had been applied to imported Graph FX slots.

**Integration boundary:** this compiler creates a separate Graph host project; it does not yet replace Main's assembled looper audio path, browser layout, or Main CLAP/VST3 session state. The running Main instrument still uses a fixed signal chain and selector routes. Do not serialize editable cable changes into a Main session or display them as an audible Patch mode until the Main compiler/host accepts them. The CV path currently accepts only LFO `out` to Filter `cutoff` with a 2,000 Hz bipolar depth; the legacy LFO has six shapes and more controls and sockets. Other voice/control edges fail explicitly. The next slices are block-boundary publication and state transfer, then the original rack shell and cable interactions. Dynamic row reflow, additional legacy module types, automation ownership for new instances, and complete project resources remain subsequent work.
