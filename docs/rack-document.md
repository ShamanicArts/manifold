# Main rack document, first control-side contract

The authored [rack catalog](../projects/main-looper/rack.json) records the legacy Main default's six active modules and seven voice/audio connections. It preserves original instance and port names such as `oscillator`, `fx1`, `__midiInput`, and `__rackOutput`. `source` is the v2 display/type name for the old `oscillator` instance. Placeholder modules are not included because the current v2 Main page does not instantiate their behavior. The original `rack_midisynth_specs.lua` and `rack_layout.lua` in the read-only checkout define the reference identities, grid, and edges.

Each module instance has a stable **string ID** for authored state and a separate stable **numeric node ID** reserved for the DSP graph and host bindings. Row, column, width and height use the original five-column, 236 × 220 cell grid. Connections name source and target instance/port IDs. Port kind is derived from the catalog; `voice`, `audio`, `cv`, and `gate` are separate. The original Lua code described several of these as generic `control`, but voice bundles and scalar modulation must remain distinct in the new engine.

The catalog now includes the physical sockets on the default ADSR, Source, Filter, FX1, FX2, EQ and LFO modules, plus the Filter Cutoff/Resonance and FX Mix parameter sockets needed for the first control route. Other patchable parameter rows are not enumerated yet. `fx1` and `fx2` are separate catalog types because the original FX1 has an auxiliary `recv` socket and a `2×2` size that FX2 does not. The compiler rejects auxiliary and unimplemented ports explicitly.

The [browser validator](../web/src/state/rack-document.js) accepts version 1 documents, rejects duplicate IDs, layout collisions, absent/reversed/mismatched ports, occupied inputs, and cycles, then returns a detached normalized value. Move, resize, add, remove, connect, replace and disconnect functions are immutable. Replacement of an occupied input validates the final document as one transaction, so a failed wire drag leaves the prior state intact. The [tests](../web/src/state/rack-document.test.js) exercise the authored default and those failure cases.

The first [audio compiler](../web/src/state/main-rack-graph.js) translates the default into the existing portable Graph runtime: MIDI input → Main voice bank → SVF → two legacy FX slots → EQ → output. ADSR is a performance/parameter face for the envelope already owned by the Main voice bank; the compiler requires its original voice route and rejects rewiring it. A deterministic [generated Graph project](../projects/main-looper/default-rack-graph.json) is accepted by the native project reader and by the Wasm worklet. The [signal verifier](../scripts/verify-main-rack-graph-wasm.mjs) shows that bypassing a low cutoff Filter by changing the authored audio edge raises a held note's energy; native and Wasm agree within 0.01% on both rendered conditions. Native save preserves parameters belonging to a disconnected Filter, and reconnecting it restores the filtered output.

The catalog now distinguishes Filter's `env` control input from its patchable `cutoff` and `resonance` parameter sockets, as in the original Lua spec and patchbay generator. The [first CV rack](../projects/main-looper/lfo-filter-rack.json) wires LFO `out` to Filter `cutoff`. It compiles to a nine-node Graph project with a sample-rate control connection. The [CV verifier](../scripts/verify-main-rack-cv-wasm.mjs) measured an 8.84× output-energy change with the wire attached; native and Wasm agree within 0.01%. Native save/reopen keeps the edge. The [browser import check](../scripts/verify-main-rack-graph-browser.mjs) opens both projects and starts audio in isolated, muted Chromium. This earlier exposed and fixed a Graph host startup bug: its standalone FX control lookup had been applied to imported Graph FX slots.

**Main instrument insert proof:** the compiler also derives a post-voice [default insert](../projects/main-looper/default-rack-insert.json) and [LFO cable insert](../projects/main-looper/lfo-filter-rack-insert.json). It removes the graph's duplicate MIDI input and voice bank, then feeds Main's existing Rust voice bank into the authored Filter → FX1 → FX2 → EQ route. A native MainInstrument test installs either prepared insert while processing is suspended. At 48 kHz and 128 frames, the default route matches the fixed chain's held-note energy (29.995070 in both paths); the LFO-to-Cutoff route yields 265.247223 and changes a real Main looper capture ring. Main's current Filter/FX/EQ controls are copied into the plan before installation, and subsequent control changes forward to active insert nodes. This proves a reusable DSP seam inside Main, not a live editable Main product.

**Browser Main startup proof:** the Main page now compiles the authored default rack document into a post-voice Graph insert on the browser control side. Its AudioWorklet builds that graph through the shared Wasm graph ABI before reporting ready, and Main's Rust/Wasm instrument consumes it before capture and monitoring. Direct Wasm verification measures 29.995072 held-note energy and 0.0076655 capture peak for the default, and 265.247227 and 0.0520200 with the LFO cable: within 0.1% of the native Main test. A muted isolated Chromium run starts the actual Main page without page errors. The existing Main LFO selector routes forward their effective Filter and FX values into the insert each block; a native signal test confirms the default insert preserves an active LFO route's output against the fixed chain.

At 48 kHz and a 128-frame capacity, the Wasm memory buffer grows from 242 MiB after the fixed Main instrument prepares to about 283.2 MiB after the insert prepares. The old fixed Filter/FX/EQ processors remain allocated as control shadows. This 41 MiB increment is a measured cost of the current seam and needs an ownership refactor before treating it as an efficient final runtime.

**Prepared live audio routing:** Main's Wasm insert now prepares its fixed node set as a patchable `ExecutionPlan`. A route message can change one typed edge between processing blocks, with no graph compilation or allocation; the graph rejects wrong signal types and edges that violate its prepared forward order. Direct Wasm verification changes FX1 IN from Filter OUT to Source audio, increasing held-note energy from 29.995 to 197.967, then reconnects Filter and measures 29.887 after its parked state resumes. A reverse EQ-to-Filter request is rejected. Only already prepared nodes can participate. The browser Main Audio Patch face now renders the six default module port panels and seven wires from the document. Dragging a copper audio socket to an input, or unplugging and reconnecting it, requests that same route operation. The document and wire update only after Wasm accepts it; a rejected route retains the prior state. A muted Chromium check exercises the UI, route acknowledgement, unplug, reconnect and version-16 session download/reopen with an edited cable. The browser-exported file also prepares and renders in native Rust.

**Integration boundary:** the browser Audio Patch face covers only audio cables among six prepared modules. Voice, CV, parameter, and other sockets are visible but disabled; the source selector routes below remain separate. The module shells still have fixed CSS placement, without the original delete, minimize, expand, drag/reorder, resize, palette insertion or dynamic row reflow. Main session version 16 carries this six-module audio rack document; browser and native Rust validate it independently and render its saved audio route. Older sessions upgrade with default cables. The native Main session exporter preserves edited routes, while a packaged CLAP/VST3 DAW roundtrip of the edited rack remains unverified. The Wasm preparation API rejects a second insert after processing starts; adding/replacing node types needs off-callback preparation, ownership handoff, old-plan retirement and state migration. The Graph LFO currently accepts only LFO `out` to Filter `cutoff` with a 2,000 Hz bipolar depth; the legacy Main LFO has six shapes and more controls and sockets. The insert and Main's old LFO status have different modulation models, so the status projection needs unification before exposure. Other voice/control edges fail explicitly. The next slices are shared saved rack state, native host loading, wider compiled port behavior, and dynamic layout and shell controls.
