# Main native host boundary

Main is a dedicated product with one assembled `MainInstrument` core. The browser `manifold_looper_*` ABI wraps that core in Wasm. The general Graph CLAP/VST3 classes load `manifold.project` graph bundles, while Standalone FX has its own product classes. A third CLAP class now accepts `manifold.main-looper` version-15 sessions through the same Main runtime; Main VST3 and native plugin editors remain open. Main stays distinct from the generic graph.

## First native slice

`manifold-native::main_instrument::MainNativeProcessor` prepares the Main core and a silent input bus before processing. Its callback accepts variable planar blocks up to the prepared limit and sorted MIDI events targeting the dedicated Main input. It validates lengths, offsets, and target IDs before changing output; a host event splits the block at its exact sample offset. The core handles Arpeggiator deadlines within each segment. This path allocates no scratch in `process`.

Native tests prove an absent input bus stays silent until a note at offset 40, the Arpeggiator's first audio starts 240 samples later at 8 kHz, a source note-off clears held state, a First Loop take records host input and plays its committed layer, and an invalid event leaves output unchanged. The Main CLAP class is now registered; VST3 class registration remains open.

`manifold-native::main_session::prepare_main_session` parses browser Main session versions 1–15 on the control side and returns a detached, fully prepared `MainNativeProcessor`. Version 15 restoration covers all four loop PCM assets, the Main Sample PCM, transport and layer metadata, the Source/ADSR/Filter/FX/EQ rack, all LFO slots and routes, control utilities, and the voice stages through Arpeggiator. Older versions leave later modules at prepared core defaults; version 3's single LFO is promoted into slot zero. The loader checks the session identity and sample rate, bounded PCM lengths, finite little-endian samples, numeric ranges, and complete FX type memories before returning a runtime. It does not publish the runtime to an audio callback. An exact browser-generated v15 fixture, populated PCM test, malformed input tests, and a native/Wasm eight-block render probe pass; the latter differs by at most 9.4e-9 per sample for a modified Filter/FX session.

`manifold-native::main_host` now supplies the host block-boundary handoff. A control endpoint parses and prepares a complete session, replacing an older pending file on that same control thread. The audio endpoint finishes its current valid block, then exchanges only Box pointers and publishes the generation for the next block. A bounded retirement queue returns the displaced runtime to the control side for destruction, so sample buffers are not freed in `process`. An invalid block leaves the pending runtime waiting. The handoff has tests for audible loop replacement, an invalid import preserving the current generation, the latest pending file winning, and concurrent control/audio threads. Main CLAP calls this runtime for audio and state; VST3 still needs its Main class. Coherent live save snapshots use the same boundary.

`manifold-native::main_host_buffers` is the prepared planar host buffer adapter for that runtime. It copies input into fixed scratch before rendering, so a CLAP or VST3 host may reuse its input pointers as output pointers without creating overlapping Rust slices. Null inputs become silence and null outputs discard the channel. The adapter copies to host output only after a valid Main block; an invalid parameter queue or oversized block leaves host output untouched. A native test compares in-place and separate buffers while a populated Main loop plays. The callback path allocates no scratch.

`MainNativeProcessor::process_host` accepts one sorted, sample-offset queue containing MIDI, fixed-ID parameters, and looper commands. It validates the full queue before changing output or state, then splits rendering at each action offset. `MainAudioRuntime::process_host` preserves the same prepared-session publication boundary. A zero-frame call can flush control actions. Fixed ID ranges in the Main project descriptor reserve transport, four layers, synth/FX/EQ, four LFOs, utilities, and voice stages. The host slice **implements** transport IDs 0–5, layer IDs 16–20 plus 8-ID stride, the authored Source/ADSR/Filter/FX/EQ synth IDs in the 256 range, four LFO slots 512–575 (five controls, six route fields, and a slot toggle for slots 2–4), ATV / Bias 640–643, Slew 672–675, Sample Hold 704–709, Compare 736–741, CV Mix 768–776, Range 800–803, Scale Quantizer 832–835, Transpose 864–866, Note Filter 896–900, Velocity Mapper 928–932, and Arpeggiator 960–965. Command IDs 0–9 use the separate `commands` map, never the host parameter range. Tests verify sample-offset Master and Arpeggiator changes, a First Loop recording command, layer volume, rejected queues, zero-frame flush, and accepted/rejected LFO, utility, and voice-stage values. The effect type switch resets prepared DSP state in place; it does no heap allocation, though its worst-case reset cost still needs real device measurement. Loadable Main plug-in classes remain open.

## Product and state contract

- Keep `projects/main-looper/project.json` as the product ID and parameter-ID source. Host parameters need fixed IDs for transport, layer controls, source, FX/EQ, and the connected voice modules. Dynamic module instances require reserved stable slots so a DAW automation lane does not change identity when a rack row moves.
- Accept the browser's versioned Main session as the portable state envelope: four loop PCM assets, sample PCM, layer/transport metadata, and rack module controls. Decode, validate, and prepare it on the host control side. Publish a complete prepared Main runtime at a block boundary; retire the old runtime away from the callback. The browser currently imports layers one at a time, so native atomic publication will be a stronger host guarantee.
- The browser's save request waits for recording and pending commits to finish, blocks control mutations during export, and copies loop/sample PCM in 4,096-frame chunks on the AudioWorklet thread. Native saving follows the same content-stability rule plus a thread handoff: the audio callback freezes transport, layer, host-parameter, FX-memory, EQ, and dynamic Sample Hold/Compare values together at a block boundary. It then copies bounded PCM chunks into two preallocated transfer blocks. The control thread assembles and validates PCM, merges these values with the imported session's UI-only choices, and serializes version-15 JSON. A loop-changing command or prepared-session publication discards an in-progress snapshot. The callback never waits for a free transfer block, allocates a block, serializes JSON, or destroys a large buffer.
- `MainControl::request_session_snapshot` and `poll_session_snapshot` produce a browser-compatible version-15 save. The source session supplies UI-only choices and module connections; the coherent audio snapshot supplies mutable DSP values. Native tests reimport a saved browser session and verify PCM, host automation, inactive FX memories, EQ, and Arpeggiator state. `cargo run -p manifold-native --example export_main_browser_session -- web/public/main-native-saved-session.json` regenerates a review file. `node scripts/verify-main-native-session-browser.mjs` opens that native file in the actual Main browser instrument, saves it again, and verifies identical loop/sample PCM plus restored controls.
- A fresh native instance prepares from the browser-authored `projects/main-looper/default-session-v15.json`, so its first native save needs no prior import. A native test reopens that save and compares note audio sample by sample. Versions 1–14 now prepare missing rack modules from the same default and promote their existing UI choices into a complete version-15 save template. Native tests exercise versions 1, 3, and 14, including an old single LFO and previously authored module values. `cargo run -p manifold-native --example export_main_browser_session -- web/public/main-native-v3-upgraded-session.json --legacy-v3` regenerates an upgraded example; the muted browser probe opens and re-saves it with identical loop/sample PCM and LFO state. The four voice stages, six control utilities, and four LFO slots record timed host edits in the same frozen value bank and export them as browser rack controls. Valid LFO control/route edits received while a slot is absent stay in the host value bank and apply when that slot is activated; removing an active slot clears its old settings, matching the browser's reset-on-removal behavior. A native test checks malformed queues, inactive edits followed by activation, removal/recreation, and all four slots. The muted browser probe confirms the original LFO 2 face and route, utility and voice faces, and identical PCM after another save. Dynamic Sample Hold and Compare outputs come from the live frozen core snapshot. Main CLAP state callbacks now use this exporter; Main VST3 state callbacks remain open.
- Keep Main's inferred First Loop tempo and host transport tempo distinct. The host supplies timeline/tempo as an explicit input; only an explicit user or project choice should adopt it. The current native slice does not yet consume host transport.

## Original Main surface in a native editor shell

`main-looper.html?editor=1` runs the original Main DOM and widget modules without starting a Web Audio engine. It accepts a Main presentation from the host bridge, restores the rack, draws the saved loop waveform, and turns widget messages into fixed host IDs using `web/src/audio/main-editor-control-map.js`. `manifold-native::main_presentation` derives this bounded document on the control side: each loop and Sample asset becomes 128 ordered peak bins, while all PCM base64 is removed. It decodes PCM in 1,024-frame chunks, retains the complete rack controls, and promotes older session versions for display without losing their layers. The authoring page keeps its existing AudioWorklet path.

The packaged Main CLAP class now registers its own X11 `clap.gui` extension and bundles the original page in the shared child webview. The IPC reader accepts bounded parameter, looper-command, and keyboard-note gestures; the parameter path emits CLAP output value events before applying them to the native Main runtime and retries when the host output queue is full. Zero-frame flushes defer MIDI until an audio block. The callback copies the browser's 20 scalar status fields for each of four layers into a seqlock-style atomic bank without allocating or consulting the renderer. The editor asks for a compact live status at 10 Hz; the webview merges it into the original transport/layer controls. A Rust IPC test proves Active Layer, Record, and MIDI enter the native audio queue, and another proves an editor parameter survives a full host output queue before reaching audio and state. The packaged C ABI probe verifies the Main GUI extension, X11 support, dimensions, and create/destroy lifecycle without opening a window. The muted browser probe verifies the actual Rust presentation and live-status UI, and fails if the editor tries to create `AudioContext`.

The packaged child window has been mounted, shown, and captured by a separate host process in isolated headless Xwayland using a populated browser-authored Main session. Both editor-ready and state-applied host callbacks fired; the screenshot shows the original Main page and its playing loop. A second in-memory host run records and stops a new First Loop take, confirms saved PCM, and captures the playing waveform plus the retrospective capture strip in that same child window. A direct DAW test remains open. The audio owner publishes one 128-bin layer, capture-strip, or Sample job per block to a fixed double-buffered atomic bank and exposes only completed 14-job frames to the editor thread. Capture bins follow the browser's old-left/new-right orientation; a native signal test checks both that ordering and a newly committed First Loop waveform. Large host blocks lower the effective visual update rate, and the worst-case callback cost still needs real-device measurement. The original session file actions now import and export through the native state boundary; LFO gate gestures remain unhandled. A standard DAW automation gesture begin/end bridge is also open. The [editor-surface review](../web/public/main-clap-editor-surface-review.html) shows the real page and these limits.

## Native Main Sample capture

The original Source widget's Live/L1–L4 selector, Retro/Free toggle, Bars slider, and Cap/STOP action now send bounded Sample IPC to the Main CLAP instance. Retro freezes a selected recent source window; Free marks the source on start and freezes its elapsed span on stop. The five capture rings and frozen buffer are already prepared in `MainInstrument`. A native control/audio mailbox carries accepted actions to the audio owner after a valid host block; the core freezes at most 4,096 stereo frames per host block, even when timed actions split that block into many render segments. Two preallocated 4,096-frame transfer chunks carry frozen PCM back to the control thread with backpressure. That thread assembles and validates PCM, creates a prepared shared source, and submits one pointer. The audio owner swaps the prepared source at a block boundary and sends the displaced shared PCM back for control-side destruction. No PCM allocation, lock, serialization, or old-source destruction occurs in the audio callback. A host session load or editor close cancels a pending capture after the next valid block.

The native signal test captures 1,000 Retro Live frames and a separate 640-frame Free Live take, hears the latter from a new note, saves the Main state, and reopens matching Sample PCM while the looper runtime generation stays unchanged. A CLAP IPC test verifies the original Sample widget message reaches the native capture request, and the muted browser editor test verifies Retro/Free messages and repaints Sample peaks and progress without creating Web Audio. Packaged release CLAP host probes click the original Source Retro Cap and Free/STOP controls in the isolated child webview, render in-memory host input, observe publication, and save 96,000-frame and 8,064-frame Samples. The first probe exposed queue writes accidentally placed inside `debug_assert!`; those writes are now unconditional in optimized builds. A direct DAW click-through and real-device timing measurement remain open. [Sample capture review](../web/public/main-clap-sample-capture-review.html) records the boundary and screenshots.

## Embedded Main session files

The original Open session input now streams its selected JSON file through bounded 2,048-byte editor IPC chunks. The CLAP control thread reassembles no more than 300 MiB, validates and prepares the Main session, and submits it through the existing block-boundary handoff. A rejected or truncated file leaves the prior state in place. The original Download button asks the native Main state exporter for the same version-15 JSON used by CLAP host saves; 16 KiB chunks pass through a bounded 32-message companion queue, with at most 16 messages handled per UI tick. The child asks for a destination with a GTK save dialog and writes on a worker thread. Neither file path touches the audio callback. The isolated host probes supply a private test destination to avoid opening a file dialog; they select a populated file through the original input, verify loop and Sample PCM in the resulting CLAP save, then click Download and compare the emitted JSON PCM. Actual GTK chooser interaction and DAW active-processing saves still need direct host validation. [Session files review](../web/public/main-clap-session-files-review.html) shows the imported page and verification details.
