# ReverseDelay migration boundary

The original `dsp/core/nodes/ReverseDelayNode.cpp` writes stereo input and feedback into a three-second delay ring. Each channel reads a window backwards, applies a triangular envelope, and mixes it with dry input. Rust graph kind 47 ports the same timing, per-sample 10 ms parameter smoothing, per-channel window state, and dormant bypass rule. The [workbench](../projects/reverse-delay/project.json) exposes delay time (`50…2000 ms`), reverse window (`20…400 ms`), feedback (`0…0.95`), and wet mix (`0…1`).

The Rust ring is allocated before audio starts. Its generation stamps make a type switch or dormant reset constant time in the audio callback, while reads from old generations return zero. This preserves the audible cleared-ring behavior of the C++ node without clearing several seconds of memory inside a callback. When target and current mix and feedback are all near zero, both versions output dry stereo and reset the ring once; a later active block starts a fresh delay.

Eight checked-in C++ captures cover default behavior, short delay/window, time and window sweeps, feedback, mix, dormant bypass, and 64-frame blocks. All eight show **Match** against Rust/Wasm with zero maximum sample difference in the tested cases. These captures include processed output that differs substantially from dry input. Standalone FX type 19 maps normalized `p/0` to `50…2000 ms`, `p/1` to `20…400 ms`, and `p/2` to feedback `0…0.95`; `p/3` and `p/4` are unused. The old Lua slot holds internal mix fully wet and applies `1.2×` wet gain before its public mix. Four new slot cases compare native Rust with Rust/Wasm. Project-level routing and preset roundtrips remain separate work.
