# Main looper migration

The behavior and visual references are read-only files under `/home/shamanic/dev/my-plugin`:

- `UserScripts/projects/Main/dsp/looper_baseline.lua` defines four layers, First Loop tempo inference, Free Mode quantization, transport, overdub, and capture-plane commands.
- `manifold/primitives/scripting/dsp_host/DSPHostLoopLayerBundle.cpp` assembles capture, playback, gate, gain, quantizer, record mode, and forward scheduler nodes. `dsp/core/nodes/LoopPlaybackNode.cpp` defines buffer replacement, repeat versus commit-length-wins overdub, and the 4,410-frame tail crossfade.
- `UserScripts/projects/Main/ui/main.ui.lua`, `ui/components/shared_transport.ui.lua`, `shared_capture_plane.ui.lua`, `looper_view.ui.lua`, and `looper_layer_strip.ui.lua` define the current Main page geometry. `manifold/ui/widgets/knob.lua` defines the rotary arc, pointer, and text layout.

## Ported behavior

`crates/manifold-core/src/main_looper.rs` owns the four prepared layers and all timing and audio rules. Each layer keeps a continuously updating 30-second stereo ring. REC marks the active layer and frame; stop either infers the closest legal bar count to target BPM or quantizes at the current BPM. Clicking a capture-plane region commits recent audio; in Traditional mode it arms a region until fired. Commits copy at most 4,096 stereo frames per process block to the inactive loop, then publish it. Existing playback continues during copying. This bounds callback work but makes a 30-second commit take about 0.94 seconds at 48 kHz with 128-frame blocks. The original C++ bundle copies in a single control call.

Layer output mixes with the monitored input. Per-layer volume, mute, signed speed/reverse, seek, play/pause, stop, clear, and the two original overdub length policies are present. Forward playback uses the old fixed 4,410-frame tail/head crossfade. The Rust core is compiled directly to native and Wasm; `crates/manifold-web` only exposes a pointer/message ABI.

Playback follows the original integer sample step at fractional speed, and a seek across more than one frame blends the old and new positions over 64 output frames. This keeps waveform scrubbing from producing the abrupt jump heard without the original seek transition.

The browser capture plane draws the original nine fixed age ranges from 16 bars on the left to 1/16 bar on the right. Each strip maps its oldest age to its left edge and newest age to its right edge: new audio enters the right edge of the 1/16 strip, travels left as it ages, then enters the right edge of each adjacent older strip. This matches the chronological order across the complete plane and the read-only C++ `RetrospectiveCaptureNode::computePeaks` bucket order. The browser queries Rust peaks in that order using 128 visual bins per strip, as in the original shared capture plane. Empty bins stay blank while the ring warms. A direct Wasm signal probe feeds loud input followed by silence and checks both the crossing between strips and movement inside a strip against the same peak bins sent to the canvases. The Rust capture ring maintains prepared 64-frame physical peak blocks so a one-frame transient is visible in a wide bin; a partially overwritten block is scanned directly until complete. This uses about 352 KiB for all four 48 kHz capture rings, with no allocation during processing. Native tests check narrow impulses and wrap against an exact per-sample oracle. Capture and committed PCM are unchanged. The 1280×720 browser panel scales uniformly in narrower BB/browser windows so none of the nine capture regions is clipped or displaced.

The prepared capture ring plus two loop buffers per layer cost about 132 MiB of stereo `f32` PCM at 48 kHz, before other Wasm memory. This preserves independent 30-second layer histories and uninterrupted playback during commits. Pooling or more compact inactive-loop storage needs an explicit continuity and callback-cost study before replacing this boundary.

The five Sample source rings and one frozen publication buffer add about 66 MiB at 48 kHz. Each source ring is capped at 1,440,000 frames to match the current sample player, so a device rate above 48 kHz shortens the maximum retrospectively sampled duration below 30 seconds. The UI reports the actual captured length.

`web/main-looper.html` follows the current shared transport, nine capture regions, and four strip layout. The rotary controls draw the geometry in `knob.lua`; the browser has no Lua runtime. Microphone permission is requested only when selected. Test tone and decoded audio file inputs work without MIDI permission. The versioned `projects/main-looper/project.json` defines stable IDs consumed by the browser adapter. Version 16 session files carry the four PCM loops, captured Main Sample PCM, Source, ADSR, Filter, FX1, FX2, EQ controls, up to four occupied Main LFO slots with their typed routes, one ATV / Bias module, one Slew module, one Sample Hold module, one Compare module, one CV Mix module, one Range Mapper module, one Scale Quantizer voice stage, one Transpose voice stage, one Note Filter voice stage, one Velocity Mapper voice stage, and one Arpeggiator voice stage. Sample Hold saves its mode, input, trigger, manual gate, held value, and previous trigger edge so it resumes without an accidental recapture. Transfers use bounded 4,096-frame chunks and reopen currently requires the same device sample rate. Versions 1–15 remain accepted with defaults for later modules; version 3 introduced one LFO route, version 4 multiple LFO slots, version 5 ATV / Bias, version 6 Slew, version 7 Sample Hold, version 8 Compare, version 9 CV Mix, version 10 Range Mapper, version 11 Scale Quantizer, version 12 Transpose, version 13 Note Filter, version 14 Velocity Mapper, and version 15 Arpeggiator. An empty Sample in version 2 or later clears a previously loaded Sample. An import publishes layers one by one, so it is not yet an atomic four-layer state switch. The browser sends its current Source state on audio restart. Version 16 also saves the six-module rack document, including supported audio cables, grid placement and the selected Rack/Patch face. Module identities and sizes remain fixed; row and column changes are validated and saved in browser and native Rust. The packaged editor now sends layout edits through an acknowledged CLAP/VST3 control-side message, with rejection restoring the prior visual placement. Older sessions receive the default route and placement. The Main page now has an explicit Hardware MIDI connection bar with permission request, device selection, note/sustain ownership and an external-browser link for views that block Web MIDI. Pitch bend and sample-accurate device timestamps remain open for Main.

`MainInstrument` owns the ported eight-voice Rust bank and four-layer looper together. It routes the synth through the shared Filter, FX1, FX2, and EQ to every capture ring and its 0.8-gain audible branch to monitoring, following Main's `midisynth_integration.lua`; host input also reaches capture and monitoring. The browser Source panel plays the bank's Wave and Sample branches, switches the six implemented blend modes, and can commit the output retrospectively. Up to four prepared LFO modules can be added or removed in the browser while running. Each has one scalar route to Filter cutoff/resonance or FX1/FX2 mix. One prepared ATV / Bias module takes a selected active LFO port and applies the original clamped bipolar amount/bias formula before its OUT can be chosen in any active route. Its original face uses the ported bidirectional compact slider; the input selector is separate patch UI. One prepared Main control Slew reads a chosen LFO port or ATV OUT and updates once per audio block using the old rise/fall milliseconds and Linear, Log, or Exp response rule. Its original face uses the ported compact sliders and dropdown. One prepared Sample Hold reads LFO, ATV, or Slew control; a chosen LFO EOC or manual gate triggers its Sample, Track, or Step mode. OUT and INV are routeable. Its face preserves `sample_hold.ui.lua`'s 236×220 geometry and colors, with source selection in an adjacent patch panel. These controls update at audio block cadence; LFO EOC captures the selected input after the block containing the edge, so a rapidly varying input may differ from a sample taken at the exact edge. The old Lua control tick may also differ from browser audio block cadence. Multiple utility instances, free routing and the wider modulation endpoint graph remain outstanding.
