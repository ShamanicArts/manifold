# Main looper migration

The behavior and visual references are read-only files under `/home/shamanic/dev/my-plugin`:

- `UserScripts/projects/Main/dsp/looper_baseline.lua` defines four layers, First Loop tempo inference, Free Mode quantization, transport, overdub, and capture-plane commands.
- `manifold/primitives/scripting/dsp_host/DSPHostLoopLayerBundle.cpp` assembles capture, playback, gate, gain, quantizer, record mode, and forward scheduler nodes. `dsp/core/nodes/LoopPlaybackNode.cpp` defines buffer replacement, repeat versus commit-length-wins overdub, and the 4,410-frame tail crossfade.
- `UserScripts/projects/Main/ui/main.ui.lua`, `ui/components/shared_transport.ui.lua`, `shared_capture_plane.ui.lua`, `looper_view.ui.lua`, and `looper_layer_strip.ui.lua` define the current Main page geometry. `manifold/ui/widgets/knob.lua` defines the rotary arc, pointer, and text layout.

## Ported behavior

`crates/manifold-core/src/main_looper.rs` owns the four prepared layers and all timing and audio rules. Each layer keeps a continuously updating 30-second stereo ring. REC marks the active layer and frame; stop either infers the closest legal bar count to target BPM or quantizes at the current BPM. Clicking a capture-plane region commits recent audio; in Traditional mode it arms a region until fired. Commits copy at most 4,096 stereo frames per process block to the inactive loop, then publish it. Existing playback continues during copying. This bounds callback work but makes a 30-second commit take about 0.94 seconds at 48 kHz with 128-frame blocks. The original C++ bundle copies in a single control call.

Layer output mixes with the monitored input. Per-layer volume, mute, signed speed/reverse, seek, play/pause, stop, clear, and the two original overdub length policies are present. Forward playback uses the old fixed 4,410-frame tail/head crossfade. The Rust core is compiled directly to native and Wasm; `crates/manifold-web` only exposes a pointer/message ABI.

Playback follows the original integer sample step at fractional speed, and a seek across more than one frame blends the old and new positions over 64 output frames. This keeps waveform scrubbing from producing the abrupt jump heard without the original seek transition.

The browser capture plane originally requested peak bins from newest to oldest inside each strip, despite arranging the strips from oldest to newest across the page. It now requests older-to-newer bins in each region, matching `RetrospectiveCaptureNode::computePeaks`' effective sample order. A direct Wasm signal probe checks loud older audio followed by quiet newer audio and an empty adjacent region. The 1280×720 browser panel scales uniformly in narrower BB/browser windows so none of the nine capture regions is clipped or displaced.

The prepared capture ring plus two loop buffers per layer cost about 132 MiB of stereo `f32` PCM at 48 kHz, before other Wasm memory. This preserves independent 30-second layer histories and uninterrupted playback during commits. Pooling or more compact inactive-loop storage needs an explicit continuity and callback-cost study before replacing this boundary.

The five Sample source rings and one frozen publication buffer add about 66 MiB at 48 kHz. Each source ring is capped at 1,440,000 frames to match the current sample player, so a device rate above 48 kHz shortens the maximum retrospectively sampled duration below 30 seconds. The UI reports the actual captured length.

`web/main-looper.html` follows the current shared transport, nine capture regions, and four strip layout. The rotary controls draw the geometry in `knob.lua`; the browser has no Lua runtime. Microphone permission is requested only when selected. Test tone and decoded audio file inputs work without MIDI permission. The versioned `projects/main-looper/project.json` defines stable IDs consumed by the browser adapter. Session files carry four PCM loops and controls, with bounded 4,096-frame transfers; reopen currently requires the same device sample rate. An import publishes layers one by one, so it is not yet an atomic four-layer state switch.

`MainInstrument` owns the ported eight-voice Rust bank and four-layer looper together. It routes the synth's raw output to every capture ring and its 0.8-gain audible branch to monitoring, following Main's `midisynth_integration.lua`; host input also reaches capture and monitoring. The browser Source panel plays the bank's Wave and Sample branches, switches the six implemented blend modes, and can commit the output retrospectively. The full MidiSynth rack UI, effects, and modulation are still outstanding.

## Validation and open boundaries

### Main Sample source checkpoint

The old `liveSampleInput` taps dry host input before the synth send. `main.lua` passes each looper layer's `gate` node as L1–L4 Sample sources; that is playback after play/pause/mute and before volume gain. `MainSampleCapture` retains all five sources in separate prepared rings, distinct from the four dry-plus-synth looper captures. Sample/Retro Cap freezes the chosen Bars window in bounded 4,096-frame pieces. Free Cap marks the selected source write position on its first press; STOP freezes the elapsed span, pinned to that source and capped to the prepared ring. Both validate and publish the sample to the eight-voice bank through bounded messages.

The browser Source module follows `Main/ui/components/source_panel.ui.lua`'s 560-pixel left graph and right Wave/Sample/Blend tabs. Bars, Root, X-Fade, Stretch, Blend, Pitch, Depth, and Output use the ported compact slider from `manifold/ui/widgets/slider.lua`. The Sample graph reads bounded chronological peak summaries from the Rust voice bank after publication; it is not a JS copy of the source audio. Wave graph draws the selected oscillator shape. Browser controls only expose implemented Rust modes: the old Noise/Pulse/SuperSaw, P-Map, FFT selection, additional wave recipe/drive and blend recipe controls are omitted until their signal paths are ported. The module sits above the looper panel as a working source checkpoint; it is not the complete historical MidiSynth tab or rack.

Native tests verify dry-only Live capture while the synth sounds, L1 gate-before-gain capture under volume and mute changes, L4 source independence, Free recording start/stop timing, and chronological Sample graph peaks. Direct Wasm tests play the Retro and Free samples after publication and read the Source graph's peak ABI; Chromium exercises Live and L1 Retro capture, L1 Free Cap/STOP, visible sample waveform, and Wave/Sample/Blend tab switching. This does not measure physical device underruns; publication runs in the worklet message handler between blocks and allocates a new sample buffer there.

Native Rust tests probe First Loop output and tempo, Free Mode length, retrospective commits across two layers, Traditional arm/fire, both overdub length policies, and loop import. A direct Node/Wasm signal test checks First Loop and a second-layer retrospective output. The Chromium check exercises the assembled page, first loop, capture-plane commit, arm/fire, waveform scrub, decoded file input, and saved-session reopen. These verify the browser path; they do not establish physical-device underrun rates.

The remaining Main boundary is the full MidiSynth rack, effects/modulation paths, native CLAP/VST3 packaging, and host transport/Link. The general graph also needs a composite loop layer and state migration if this instrument is to become an editable graph product. Legacy Main preset import and sample-rate conversion for saved sessions remain open. The old retrospective buffer is always on, so a live input reaches all four captures even when no loop is playing. The standalone looper page must not be presented as the complete Main instrument.
