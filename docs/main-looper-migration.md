# Main looper migration

The behavior and visual references are read-only files under `/home/shamanic/dev/my-plugin`:

- `UserScripts/projects/Main/dsp/looper_baseline.lua` defines four layers, First Loop tempo inference, Free Mode quantization, transport, overdub, and capture-plane commands.
- `manifold/primitives/scripting/dsp_host/DSPHostLoopLayerBundle.cpp` assembles capture, playback, gate, gain, quantizer, record mode, and forward scheduler nodes. `dsp/core/nodes/LoopPlaybackNode.cpp` defines buffer replacement, repeat versus commit-length-wins overdub, and the 4,410-frame tail crossfade.
- `UserScripts/projects/Main/ui/main.ui.lua`, `ui/components/shared_transport.ui.lua`, `shared_capture_plane.ui.lua`, `looper_view.ui.lua`, and `looper_layer_strip.ui.lua` define the current Main page geometry. `manifold/ui/widgets/knob.lua` defines the rotary arc, pointer, and text layout.

## Ported behavior

`crates/manifold-core/src/main_looper.rs` owns the four prepared layers and all timing and audio rules. Each layer keeps a continuously updating 30-second stereo ring. REC marks the active layer and frame; stop either infers the closest legal bar count to target BPM or quantizes at the current BPM. Clicking a capture-plane region commits recent audio; in Traditional mode it arms a region until fired. Commits copy at most 4,096 stereo frames per process block to the inactive loop, then publish it. Existing playback continues during copying. This bounds callback work but makes a 30-second commit take about 0.94 seconds at 48 kHz with 128-frame blocks. The original C++ bundle copies in a single control call.

Layer output mixes with the monitored input. Per-layer volume, mute, signed speed/reverse, seek, play/pause, stop, clear, and the two original overdub length policies are present. Forward playback uses the old fixed 4,410-frame tail/head crossfade. The Rust core is compiled directly to native and Wasm; `crates/manifold-web` only exposes a pointer/message ABI.

Playback follows the original integer sample step at fractional speed, and a seek across more than one frame blends the old and new positions over 64 output frames. This keeps waveform scrubbing from producing the abrupt jump heard without the original seek transition.

The browser capture plane draws the original nine fixed age ranges from 16 bars on the left to 1/16 bar on the right. Each strip maps its oldest age to its left edge and newest age to its right edge, matching `RetrospectiveCaptureNode::computePeaks` in the C++ source. New audio starts at the right of the 1/16 strip, travels left as it ages, then enters the right of each adjacent older strip. Empty bins stay blank while the ring warms. A direct Wasm signal probe feeds loud input followed by silence and checks both the crossing between strips and movement inside a strip against the same peak bins sent to the canvases. The Rust capture ring maintains prepared 64-frame physical peak blocks so a one-frame transient is visible in a wide bin; a partially overwritten block is scanned directly until complete. This uses about 352 KiB for all four 48 kHz capture rings, with no allocation during processing. Native tests check narrow impulses and wrap against an exact per-sample oracle. Capture and committed PCM are unchanged. The 1280×720 browser panel scales uniformly in narrower BB/browser windows so none of the nine capture regions is clipped or displaced.

The prepared capture ring plus two loop buffers per layer cost about 132 MiB of stereo `f32` PCM at 48 kHz, before other Wasm memory. This preserves independent 30-second layer histories and uninterrupted playback during commits. Pooling or more compact inactive-loop storage needs an explicit continuity and callback-cost study before replacing this boundary.

The five Sample source rings and one frozen publication buffer add about 66 MiB at 48 kHz. Each source ring is capped at 1,440,000 frames to match the current sample player, so a device rate above 48 kHz shortens the maximum retrospectively sampled duration below 30 seconds. The UI reports the actual captured length.

`web/main-looper.html` follows the current shared transport, nine capture regions, and four strip layout. The rotary controls draw the geometry in `knob.lua`; the browser has no Lua runtime. Microphone permission is requested only when selected. Test tone and decoded audio file inputs work without MIDI permission. The versioned `projects/main-looper/project.json` defines stable IDs consumed by the browser adapter. Version 6 session files carry the four PCM loops, captured Main Sample PCM, Source, ADSR, Filter, FX1, FX2, EQ controls, up to four occupied Main LFO slots with their typed routes, one ATV / Bias module, and one Slew module with their input selections. Transfers use bounded 4,096-frame chunks and reopen currently requires the same device sample rate. Versions 1–5 remain accepted, including version 3’s one LFO route, version 4’s multiple LFO slots, and version 5’s ATV / Bias module. An empty Sample in version 2 or later clears a previously loaded Sample. An import publishes layers one by one, so it is not yet an atomic four-layer state switch. The browser sends its current Source state on audio restart.

`MainInstrument` owns the ported eight-voice Rust bank and four-layer looper together. It routes the synth through the shared Filter, FX1, FX2, and EQ to every capture ring and its 0.8-gain audible branch to monitoring, following Main's `midisynth_integration.lua`; host input also reaches capture and monitoring. The browser Source panel plays the bank's Wave and Sample branches, switches the six implemented blend modes, and can commit the output retrospectively. Up to four prepared LFO modules can be added or removed in the browser while running. Each has one scalar route to Filter cutoff/resonance or FX1/FX2 mix. One prepared ATV / Bias module takes a selected active LFO port and applies the original clamped bipolar amount/bias formula before its OUT can be chosen in any active route. Its original face uses the ported bidirectional compact slider; the input selector is separate patch UI. One prepared Main control Slew reads a chosen LFO port or ATV OUT and updates once per audio block using the old rise/fall milliseconds and Linear, Log, or Exp response rule. Its original face uses the ported compact sliders and dropdown. Its OUT is available to Filter and FX mix routes. The old Lua control tick may differ from the browser audio block cadence, so exact step timing between hosts remains to be compared. Multiple utility instances, free routing and the wider modulation endpoint graph remain outstanding.

## Validation and open boundaries

### Main Sample source checkpoint

The old `liveSampleInput` taps dry host input before the synth send. `main.lua` passes each looper layer's `gate` node as L1–L4 Sample sources; that is playback after play/pause/mute and before volume gain. `MainSampleCapture` retains all five sources in separate prepared rings, distinct from the four dry-plus-synth looper captures. Sample/Retro Cap freezes the chosen Bars window in bounded 4,096-frame pieces. Free Cap marks the selected source write position on its first press; STOP freezes the elapsed span, pinned to that source and capped to the prepared ring. Both validate and publish the sample to the eight-voice bank through bounded messages.

The browser Source module follows `Main/ui/components/source_panel.ui.lua`'s left graph and right Wave/Sample/Blend tabs. Wave render, Sample pitch, and Blend key tracking use the original segmented-control form. Bars, Root, X-Fade, Stretch, Blend, Pitch, Depth, and Output use the ported compact slider from `manifold/ui/widgets/slider.lua`. The Sample graph reads bounded chronological peak summaries from the Rust voice bank after publication; it is not a JS copy of the source audio. Wave graph draws the selected oscillator shape. Browser controls only expose implemented Rust modes: the old Noise/Pulse/SuperSaw, P-Map, FFT selection, additional wave recipe/drive and blend recipe controls are omitted until their signal paths are ported. The shared transport and capture plane sit at their original y=0 and y=52 offsets; the two full-width tabs begin at y=182. The MidiSynth tab places ADSR at rack x=0, Source at x=236, and Filter at x=708. The Source panel follows the legacy resize behavior at 472×208 inside its shell. This is a working first rack row, not the complete historical MidiSynth rack.

The browser ADSR graph follows `Main/ui/behaviors/envelope.lua` with a 0.5-second sustain display span and draggable Attack, Decay, and Sustain points. Four compact sliders expose the original millisecond and percent values. Changes map to the Rust bank's seconds/fraction parameter IDs 11–14, so notes and both sample/wave paths receive the same envelope. `projects/main-looper/project.json` now names the exposed synth parameter IDs, and the browser and direct Wasm verifier consume that contract rather than repeating numeric IDs. A direct Wasm probe checks that increasing Attack changes the signal over time. The shared Filter slot follows `Main/dsp/midisynth_integration.lua`: the Rust SVF receives the voice-bank mix before the synth signal reaches looper capture and the 0.8-gain monitor branch. Dry host input bypasses it. The UI uses the old wide 472×208 Filter layout, its mode menu, cutoff/resonance compact sliders, and a draggable response graph. `projects/main-looper/project.json` fixes Filter IDs 21–23. The legacy control range exposes resonance to 2 while the DSP clamps it to 1; the v2 kernel preserves that boundary for now. Native and direct Wasm signal probes verify that a low cutoff reduces a high note while the dry input remains unchanged. The eight-band EQ follows Filter in the same Rust signal path. It uses stable IDs 64–105: eight groups of enabled/type/frequency/gain/Q plus output and mix. The compact panel follows the original `eq.ui.lua` 236×208 geometry and the original graph interactions: click to add, drag to set frequency and gain or Q, wheel for Q, double click to remove, and selected-band field edits. A 108-bin snapshot reads the actual Rust filter coefficients at UI cadence; the graph never drives audio timing. The second-row panel is shifted 13 px upward from the Lua rack coordinate so its shell ends at the keyboard boundary. The two 472×208 FX panels use the same shift. They expose all 21 legacy effect types through the original wide FX slot layout, with per-type normalized parameter memory, XY assignment, XY/filter-graph interaction, compact slider ports, and two serial Rust `EffectSlot` processors. The slots default to zero mix. Their kernels and scratch are prepared before the audio callback; a 48 kHz/2,048-frame Main Wasm instance currently reserves about 243 MiB total. Native tests confirm both FX slots change monitor and retrospective capture in sequence while dry host input bypasses them.

Native tests verify dry-only Live capture while the synth sounds, L1 gate-before-gain capture under volume and mute changes, L4 source independence, Free recording start/stop timing, and chronological Sample graph peaks. Direct Wasm tests play the Retro and Free samples after publication and read the Source graph's peak ABI; Chromium exercises Live and L1 Retro capture, L1 Free Cap/STOP, visible sample waveform, and Wave/Sample/Blend tab switching. This does not measure physical device underruns; publication runs in the worklet message handler between blocks and allocates a new sample buffer there.

Native Rust tests probe First Loop output and tempo, Free Mode length, retrospective commits across two layers, Traditional arm/fire, both overdub length policies, and loop import. A direct Node/Wasm signal test checks First Loop and a second-layer retrospective output. The Chromium check exercises the assembled page, first loop, capture-plane commit, arm/fire, waveform scrub, decoded file input, and version 2 session reopen with rack and captured Sample restoration. It also checks the original strip waveform and knob x positions. These verify the browser path; they do not establish physical-device underrun rates.

The remaining Main boundary is general dynamic rack mutation, multiple utility instances and wider endpoint routing, native CLAP/VST3 packaging, and host transport/Link. The general graph also needs a composite loop layer and state migration if this instrument is to become an editable graph product. Legacy Main preset import and sample-rate conversion for saved sessions remain open. The old retrospective buffer is always on, so a live input reaches all four captures even when no loop is playing. The browser Main page has connected Looper and partial MidiSynth tabs; it must not be presented as the complete historical instrument.

## Main LFO and typed Filter route

[Visual and signal review](../web/public/main-modulation-review.html).

The third rack row now displays the legacy 236×220 LFO component geometry and original compact Rate, Depth, Phase, and Retrig controls. Rust owns Sine, Triangle, Saw, Square, sample and hold, and interpolated noise; OUT, INV, UNI, and EOC are typed scalar outputs. Reset and sync gates follow the old edge and hold behavior. One route connects a selected output to shared Filter cutoff or resonance, with Add or Replace, Amount, Bias, and Enable. Add uses the legacy centered bipolar contribution; Replace maps frequency exponentially. The unmodulated Filter value stays as its base control and returns when the route is disabled. The core advances at audio sample rate and applies its effective Filter target once per audio block; the original Lua runtime updates at a UI control cadence.

The direct Wasm probe measures a held high note with square LFO cutoff changing from 1,608 to 4,792 Hz; sounding sample energy rises from 10.75 to 19.22 over equal windows. A second prepared LFO independently drives FX1 mix from 1.00 to 0.00; the direct Wasm probe measures sounding energy rising from 0.23 to 19.22 when the low-pass FX route opens. Chromium adds that module while running, routes it to FX1 mix, saves and reopens both LFOs through session version 5, then removes it. One prepared ATV / Bias module accepts a selected LFO output and can feed any of those four targets through an existing active route. Direct Wasm changes its Amount from −1 to +1 and observes FX1 mix 0 → 1 and held-note energy 38.43 → 0.57. Chromium verifies its original-size face, bidirectional sliders, patch connection, and version 5 save/reopen; versions 1–4 still import. The rack still lacks multiple ATV instances, multiple routes per LFO, visual patch cables, and the full legacy endpoint graph. [ATV review](../web/public/main-atv-bias-review.html) shows this checkpoint.

The Main Slew continues that typed chain. A native trace checks the original Lua rise, fall, and shape calculations; a Main instrument test checks an ATV input reaching Slew OUT and FX1 mix. Direct Wasm routes held ATV +1 through a 1,000 ms linear rise, reading Slew OUT at 0.016 after one 128-frame block at 8 kHz and 0.983 after further blocks; the sounding FX1 signal changes from energy 6.13 to 0.65 over equal windows. Chromium checks the 236×220 original face, the ported dropdown and compact sliders, the typed input selector, Slew OUT route selection, and version 6 save/reopen with version 5 fallback defaults. [Slew review](../web/public/main-slew-review.html) shows the live face and route.

Each slot owns one route; routes to the same target apply in ascending slot order. Add composes with the current value and a later Replace supersedes earlier contributions. Four slots are prepared before processing, and deactivating a slot clears its route so the target returns to its base on the next block. The current browser keeps slot zero as the base LFO and lets users add or remove slots one through three. [Live rack review](../web/public/main-rack-mutation-review.html) shows the second module and its FX mix connection.
