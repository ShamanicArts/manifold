# Standalone FX migration boundary

The old `UserScripts/projects/Standalone_FX/manifold.project.json5` exports a **single swappable effects slot**, not a chain. Its public host parameters are `type` (0–20), `mix` (0–1), and five normalized context-dependent controls `p/0`–`p/4`. Type 0 is Chorus. The default mix is zero, so its initial output is dry. The Lua `fx_slot.lua` instantiates the selected effect on demand, gates unselected instances, and combines dry/wet through gain and mixer nodes. `fx_definitions.lua` maps the same normalized controls to different physical units for each effect.

Types 3, 6, and 8 use `CompressorNode`, `SVFNode`, and `StereoDelayNode`, respectively, which now have individual Rust ports. Type 2 is the legacy `WaveShaperNode`, **not** the `DistortionNode` currently ported in v2. The v2 [FX chain project](../projects/fx-chain/project.json) deliberately wires `Distortion → StereoDelay → SVF` for composition testing and is not a Standalone FX preset or a substitute for type selection. Its four offline cases compare native Rust with Rust/Wasm because this exact chain has no old C++ fixture.

The current [slot slice](../projects/standalone-fx-slice/project.json) preserves type IDs 3, 6, and 8, wet mix, and normalized `p/0`–`p/4` paths. It shows only those three supported types and runs the selected kernel. All kernels are prepared in advance, so the unused delay still occupies memory. Switching types clears the newly selected effect state and drops its previous tail; it does not yet reproduce the old gain/mixer envelope or legacy preset roundtrips. Nine offline cases compare native Rust with Rust/Wasm, not the complete old plug-in.

Type 3 maps normalized controls to threshold `−40…−2 dB`, ratio `1.5…20`, attack `1…40 ms`, release `20…250 ms`, and knee `0…12 dB`, matching the old Lua definition. Its old scalar C++ node ignores knee and only calculates attack/release coefficients when prepared. Selecting type 3 builds a fresh compressor from the stored normalized values. Changes to threshold and ratio take effect while running; attack and release changes require switching away and back, or restarting audio with the current selection. The browser now sends the selected type and its five values at graph preparation, so a stopped workbench restart uses the displayed timing settings. The individual [Compressor comparison](compressor-migration.md) has C++ fixtures; the slot comparison remains native Rust versus Wasm because old project-level routing has no fixture here.

A faithful full Standalone FX port should preserve the public type IDs and normalized host controls, explicitly map each supported type to its physical parameters, and mark unsupported types unavailable rather than silently substituting another effect. Only the selected kernel should run in the audio callback. A change of type needs a prepared replacement plan published at a block boundary, with a stated policy for the previous tail and parameter values. The current graph cannot replace a live plan or migrate a delay buffer; that state contract must precede a host-facing preset migration. The old checkout remains the behavior reference and is not edited here.
