# Standalone FX migration boundary

The old `UserScripts/projects/Standalone_FX/manifold.project.json5` exports a **single swappable effects slot**, not a chain. Its public host parameters are `type` (0–20), `mix` (0–1), and five normalized context-dependent controls `p/0`–`p/4`. Type 0 is Chorus. The default mix is zero, so its initial output is dry. The Lua `fx_slot.lua` instantiates the selected effect on demand, gates unselected instances, and combines dry/wet through gain and mixer nodes. `fx_definitions.lua` maps the same normalized controls to different physical units for each effect.

Types 6 and 8 use `SVFNode` and `StereoDelayNode`, respectively, which now have individual Rust ports. Type 2 is the legacy `WaveShaperNode`, **not** the `DistortionNode` currently ported in v2. The v2 [FX chain project](../projects/fx-chain/project.json) deliberately wires `Distortion → StereoDelay → SVF` for composition testing and is not a Standalone FX preset or a substitute for type selection. Its four offline cases compare native Rust with Rust/Wasm because this exact chain has no old C++ fixture.

A faithful Standalone FX slice should preserve the public type IDs and normalized host controls, explicitly map each supported type to its physical parameters, and mark unsupported types unavailable rather than silently substituting another effect. Only the selected kernel should run in the audio callback. A change of type needs a prepared replacement plan published at a block boundary, with a stated policy for the previous tail and parameter values. The current graph cannot replace a live plan or migrate a delay buffer; that state contract must precede a host-facing preset migration. The old checkout remains the behavior reference and is not edited here.
