# Main rack Note Filter migration boundary

The old Main rack `note_filter_runtime.lua` passes a voice when its note lies inside the inclusive low/high range, or outside it in Outside mode. It sorts reversed bounds and rounds low/high to the nearest MIDI note. Blocked voices have their gate and amplitude cleared. The old rack's two Lua tests confirm that behavior.

The old `export_midi_effects.note_filter` adapter uses `voice_transform.lua`. That adapter reads the filtered voice's pitch but ignores its gate when emitting MIDI. In the [offline probe](../tools/legacy-midi-note-filter.lua), a default out-of-range note 20 still produces note-on/off, and switching to Outside mode restarts held note 60 even though the rack would silence it. The [event comparison](../artifacts/reviews/checkpoint-98-midi-note-filter-events.json) records six old export events against two Rust events. We chose the rack's audible gate behavior for v2; preserving the export's forwarded blocked notes would make a Note Filter that fails to filter.

The Rust [`MidiNoteFilter`](../crates/manifold-core/src/midi_note_filter.rs) uses the same fixed eight-slot note ownership as [`MidiTranspose`](../crates/manifold-core/src/midi_transpose.rs). A blocked key remains owned without sounding. Moving the range or mode while a key is held sends offs for sounding notes before ons for newly admitted notes. Note-off uses the original channel and pitch; pitch bend passes through. The effect emits into a caller-owned 16-event array and allocates nothing on the audio thread.

The [browser workbench](../projects/midi-note-filter/project.json) uses `MidiInput → MidiNoteFilter → VoiceSynth` in the typed Rust graph. Its on-screen keyboard works without hardware MIDI permission. One native Rust audio case switches from Inside to Outside while a passing C4 and blocked G♯0 are held. Direct Wasm, the actual AudioWorklet adapter, and the workbench's comparison renderer reproduce all 8,192 stereo frames exactly. See the [verification metrics](../artifacts/reviews/checkpoint-98-midi-note-filter-metrics.json).

The workbench now shows incoming events beside a bounded Rust output trace. Blocked note-on/off events are marked explicitly, while parameter changes show the emitted off/on pair. The trace is polled off the callback at 10 Hz and retains the latest 32 events.
