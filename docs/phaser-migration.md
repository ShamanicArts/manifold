# Stereo Phaser migration boundary

The new `Phaser` kernel ports the original `dsp/core/nodes/PhaserNode.cpp` scalar stereo path. The legacy node needs JUCE for buffer views, limits, and π; the Rust kernel uses planar slices, fixed twelve-stage state arrays, and standard math. No JUCE code runs in v2.

The node has one stereo audio input and output. Parameter IDs are 0 sweep rate (0.1–10 Hz), 1 depth (0–1), 2 stage count (6 or 12, threshold 9), 3 feedback (−0.95…0.95), and 4 stereo spread (0–180 **degrees**). Rate, depth, feedback, and spread use the original 10 ms one-pole smoothing; stage count switches immediately. An LFO sweeps each channel’s all-pass coefficient around 900 Hz with a 700 Hz depth range. The right LFO adds spread/360 phase. Each channel feeds its last all-pass output back before the cascade and blends half dry plus half phased output.

The browser workbench exposes physical values, including degrees. The old Main rack wrapper in `UserScripts/projects/Main/lib/fx_definitions.lua` sends a normalized 0–1 value directly to `setSpread`, although the C++ setter expects degrees. Its audible stereo spread is therefore very small. The Standalone FX slot slice preserves that narrow rendered spread for type 1; the standalone primitive preserves the C++ node’s physical contract. A future preset importer must still choose an explicit compatibility policy.

Seven checked-in C++ cases cover stereo input, six/twelve-stage switching, rate/depth changes, negative feedback, 0–180° spread, slow sweep, and 64-frame blocks. Native Rust differs by at most 0.00000054 per sample on this machine; the parity gate is 0.00001. Rust/Wasm compares against the same C++ fixtures in the browser. The node has no meter beyond its audible output; the workbench shows the output spectrum and stereo peak comparison.
