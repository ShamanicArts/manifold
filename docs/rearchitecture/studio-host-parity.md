# Studio host parity, 10 October 2026

## Vite app entry, 10 October

The browser creator now opens at `/` and the DSP example library at `/library` from one Vite `index.html` mount document. The native creator webview also points at that built root document. The former `studio.html` and `primitives.html` pages are removed; the Vite server redirects their old URLs, preserving query parameters. `/workbench.html` retains the earlier primitive workbench. Studio starts with an egui canvas and hidden compatibility controls, so the old “DSP live scripting” heading cannot appear while Studio initializes. Project and presentation source, graph, and the face still come from the accepted project.

This is a **route and host bootstrap correction**, not a claim that all Manifold demos or the standalone native app have been collapsed into one SPA. The shared `filter.js` bootstrap still contains legacy library behavior, and other prototype HTML entries remain; extracting the runtime adapter and migrating those routes is outstanding. The native creator URL is updated for Linux, macOS and Windows, but this change has only been exercised in a native client simulation, not a live DAW window. A browser production preview and Vite dev run loaded Nacre at `/` and the Orbit library at `/library` without page errors; the public 4174 URL redirected the old Studio link and held one navigation over nine seconds. Local Streamable HTTP MCP listed 29 tools and inspected the new live Studio project. Bundle updates now use Vite's own dev server; project source edits continue through the live MCP bridge.

### Browser project persistence

The Nacre project embeds roughly 2 MB of media. Writing `runtime.save()` to `localStorage` on every `display()` call exhausted its shared quota and could throw before the editor finished mounting. Full project snapshots now use IndexedDB, with serialized, delayed writes outside rendering. A `?resume=1` load reads the saved snapshot; an existing legacy `localStorage` snapshot migrates to IndexedDB and is removed only after a successful write. Visiting the linked project without `resume=1` no longer overwrites that saved draft before the user edits. An unavailable project database is surfaced in the editor and pauses autosave rather than silently replacing an unread draft. In a real browser, a 4.5 MB filled `localStorage` still allowed a Nacre parameter edit to persist and reopen from IndexedDB; an older local snapshot migrated and cleared without page errors.

The Studio workspace in `crates/manifold-app/src/studio.rs` is the presentation contract for native and browser. Both compile that egui code. It owns the graph, inspector, source tabs, source actions, input selector, monitor control, pane geometry and selection. The browser host embeds CodeMirror and the authored Three.js face as DOM content inside its published geometry. The Linux native host embeds the same CodeMirror modules and authored face as Wry child surfaces inside the same geometry. Host callbacks own audio; neither editor nor face owns the DSP graph.

Focus graph hides the embedded CodeMirror and face, then Workspace restores both at the previous split. The browser focus round trip was exercised through the visible controls.
- Native Open project opens a GTK chooser; browser Open project invokes its file input. The source editor preserves a dirty draft when accepted source changes. Graph edits are blocked while project or presentation source is dirty.
- The browser source workflow was exercised through the visible controls: apply advanced revision 0 to 1; reset restored the original source at revision 2. The shared monitor control changed the browser host volume from 0.12 to 0.29 and back. Project/Presentation changed the actual CodeMirror document. Native Nacre was captured with both child surfaces mounted and its audio routed to a private null sink.

## Shared graph editing added in the next slice

- **Add node** opens a shared egui modal beside the graph action in browser and native. A focused search sits above a compact, color-filled category grid; the lower two columns pair a scrollable node list with an inspector showing a short description, primitive ID, parameter count, and actual input/output port names and signal kinds. The insert action stays in that inspector. Mouse, Up/Down and Alt+Left/Right navigate results and categories; Enter inserts. The catalog includes saved modules and omits host-owned structural input/output/monitor nodes. The modal is outside the graph inspector, so selection there does not displace the current graph inspector.
- In the production browser build, the graph toolbar opened the modal, Filters & EQ reduced the 42-entry catalog to four results, searching `svf` reduced it to two, and hovering SVF updated the inspector without inserting it. Clicking **Insert SVF filter** accepted `graph.add` at revision 1 and raised the node count from 12 to 13; Undo restored 12 nodes at revision 2. The standalone native release rendered the same modal while its audio stream used `manifold_review_null` on inactive workspace 16; the user's BB window retained focus.
- The graph supports two-axis panning by empty-space drag or minimap, reset to Origin, and 30–300% zoom in both hosts. Ctrl+wheel/pinch zooms around the pointer; panning has no zero boundary. Zoom scales node cards, ports, cables and minimap positions together. Shift-click multi-selects nodes. A named visual group is authored into `studioGraph.groups`, appears around its members in both hosts, and can be removed without deleting nodes or cables. This is a **layout group**, not a DSP composite module or a move-together group yet.
- Group, ungroup and position edits take a bounded metadata path only when source analysis proves `studioGraph` is used solely by `applyStudioGraph` and `editorGraph`. Other scripts take the normal full source-evaluation path. The native JS controller now forwards `updateMetadata` to a distinct native host command. It validates that the DSP project is unchanged and acknowledges the revision at an audio block boundary without preparing a replacement processor. ## Graph canvas and node controls, 10 October

- Right-clicking empty graph space opens **Add node here** and **Center view here** at the pointer. Right-clicking a node offers Inspect, Remove, and **Add node beside**, which searches for nearby free space. The toolbar Add node uses the last graph click or the viewport center. New positions and node drags write absolute world coordinates into the same source-backed `studioGraph.layout` in browser and native; existing fractional coordinates remain readable. The view resolves collisions among older fractional positions without silently rewriting the project. The agent graph commands accept the same world positions.
- The canvas camera is unbounded in X and Y. In the production browser build, Ctrl+wheel at the pointer changed zoom from 100% to 142%; dragging then moved the camera to `[-107.05, -169.16]`. The workspace inspection API publishes camera, zoom, viewport, and node rectangles so an agent can target the graph without inventing a separate coordinate system.
- Cards now show primitive category color, named ports, parameter/live counts, up to two inline kit controls (four when selected), and an **EXPOSE** action for unexposed parameters. In a live Nacre browser session, an oscillator was added with a source-backed world position, its waveform was exposed as `/studio/oscillator/16/waveform`, and the newly synthesized card control changed the accepted runtime value from Sine (`0`) to Square (`2`). The authored source and control survived reload. The automation tab was then reset to the canonical Nacre project for paired measurement and review.
- The graph canvas clips node paint, ports, hit targets and inline controls to its viewport. A clean reload with the camera shifted had shown offscreen controls painting over the toolbar; the [panned canvas capture](../../web/public/nacre/2026-10-10-graph/evidence/studio-browser-graph-clipped.jpg) verifies the fix in the current build.
- [Browser context menu](../../web/public/nacre/2026-10-10-graph/evidence/studio-browser-graph-context.jpg), [picker from that menu](../../web/public/nacre/2026-10-10-graph/evidence/studio-browser-graph-context-picker.jpg), and [live card control](../../web/public/nacre/2026-10-10-graph/evidence/studio-browser-graph-control.jpg) show the interaction. - The [paired graph-edit run](../../web/public/nacre/2026-10-10-graph/evidence/paired-graph-canvas-benchmark.json) made six group/ungroup edits per host on canonical Nacre. Browser p50/p95 were **101.8/185.2 ms**, with audio stopped. Native release p50/p95 were **2018.1/2027.0 ms**, with audio blocks advancing on the private null sink. Signal topology was unchanged and group count restored. This confirms the earlier native remote-edit latency gap; these timings do not measure DSP throughput or an audible browser/native performance ratio.

The graph now supports adding, wiring, exposing, positioning and grouping existing primitives through the visual client, script and agent operations. A complete product graph built solely from visual edits still needs richer per-node configuration, reusable user-authored node definitions, and parity for every legacy behavior; the Nacre device remains an authored project rather than proof that all Manifold products can be assembled from the graph UI.

### Paired measurement

Run `scripts/benchmark-studio-hosts.mjs` with **both** a browser CDP connection from `bb browser connection` and the native app's local agent endpoint. The script refuses a single-host run, performs the same Nacre group/ungroup edits on each, and checks that signal topology and initial targets remain unchanged, group count is restored, and native audio blocks advance. Run with production browser assets and a release native binary, recording audio state and window visibility beside the numbers. Repeat this paired procedure whenever graph editing or frame scheduling changes.

On 10 October, the [final paired run](../../web/public/nacre/2026-10-10-graph/evidence/paired-studio-benchmark.json) accepted six edits per host: browser p50 **89 ms**, p95 **119 ms** with audio stopped; native release p50 **2013 ms**, p95 **2022 ms** with audio running on the private null sink and its window on an inactive workspace. A separate 20-edit browser run was p50 79 ms/p95 140 ms; an 11-edit native run was p50 2009 ms/p95 2039 ms. The native result is a serious remote-edit latency gap; the inactive window may be frame throttled, so these figures do **not** isolate the host adapter or compare DSP throughput. Its previous command reported 857 ms from JS command publication to audio acknowledgement. The authored signal stayed unchanged and audio block count advanced. Measure a visible, nonintrusive native app and a browser with safely routed audio before drawing audio-performance conclusions.

## Still different

- Browser audio file and microphone input are enabled. The native host currently implements saw, noise and silent input; file and microphone options are shown as unavailable. Add native input adapters and validate their audio routing before enabling them.
- Browser starts its AudioWorklet after a user gesture. Native starts its CPAL stream on launch. The common Studio presents the host state, but these device lifecycles remain host-specific.
- Browser export and Web MCP use browser/cloud services; the native Agent panel exposes its local endpoint. Export and agent presentation need a shared capability model and equivalent native workflows.
- Host input uses inline kit choices so every option stays visible above the embedded editor. Other egui popups that cross an embedded surface still need an explicit popup layer and pointer ownership contract on both hosts.
- Native macOS and Windows child WebView portals remain to be implemented and visually checked. Linux WebKitGTK is the tested native portal.

The acceptance bar for parity is an interactive product slice on each host, not matching screenshots alone: edit both sources, apply without stopping audio, drag a kit control, select and clear graph nodes, resize panes and the window, open/save, and verify the authored face and agent operations against one accepted project revision.

## Nacre face and native edit latency follow-up, 10 October

The authored Nacre face no longer draws the gold hairline seam, short branches, concentric filament/iris rings, or the audio-driven light ring. The Chladni contours, particles, crystalline rim, control panel and rainbow tubes remain. The [browser](../../web/public/nacre/2026-10-10-graph/evidence/nacre-face-clean-browser.jpg) and [standalone native](../../web/public/nacre/2026-10-10-graph/evidence/nacre-face-clean-native.jpg) captures show the same saved project after the change.

The earlier native 2-second graph-edit result was primarily an inactive-window scheduling effect. Even a read-only `project.inspect` took about 1 second: eframe's blocking OpenGL vsync swap was paced by the compositor while the window was on inactive workspace 16. Disabling that swap wait reduced repeated inspect calls to 6–12 ms. Requesting an immediate repaint alone did not change the 1-second cadence. A separate native QuickJS cost remained: group/ungroup called Acorn repeatedly on the roughly 50 KB authored source. Caching the accepted and proposed syntax trees reduced the script part of an edit from about 180–225 ms to 19–26 ms. Neither change moves graph compilation or UI work into the audio callback.

The [final paired release benchmark](../../web/public/nacre/2026-10-10-graph/evidence/paired-studio-after-native-latency-fix.json) ran 20 group/ungroup edits per host, preserved signal topology and restored the initial group count. Browser, with audio stopped, measured **41.4 ms p50 / 55.6 ms p95**. Standalone native, with audio blocks advancing into `manifold_review_null` on the inactive workspace, measured **64.3 ms p50 / 85.0 ms p95**. This is an edit-acknowledgement comparison under stated host conditions, not a DSP throughput or audible performance comparison. Unfocused egui repainting is throttled while commands wake immediately; observed idle process CPU on the inactive workspace fell from about 70% to 10% of one core. The native renderer now runs without swap pacing; revisit that choice if visible tearing or power use becomes measurable on supported desktops.
