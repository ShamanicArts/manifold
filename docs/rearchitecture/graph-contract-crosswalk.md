# Graph authoring crosswalk: legacy contract to v2

Status: R00 in progress, 29 September 2026. This records concrete Main and host behaviors found in the read-only historical checkout. It is not the 28-project inventory, a completed API design, or permission to retire unsupported behavior. The [recovery register](README.md) defines the acceptance gates; the [Main ledger](main-recovery-ledger.md) tracks the audio ownership change.

## The product boundary exposed by the old code

`UserScripts/projects/Main/dsp/main.lua:24` defines `buildPlugin(ctx)`. It attaches looper and synth modules, constructs host input/trim/monitor, fans input into four layer capture inputs, mixes the synth send and layer outputs, and marks a master gain as monitor/output. It uses graph connections among primitives; it does not instantiate a single monolithic Main processor. `Main/dsp/midisynth_integration.lua` creates Filter, FX, EQ, spectrum, voice and sample nodes and changes connections in response to project controls. `Main/ui/behaviors/rack_mutation_runtime.lua` creates/deletes palette modules, updates the rack and connection document, and causes graph and modulation routing changes. This establishes graph authoring, graph lookup, mutation, and UI projection as Main behavior, alongside the DSP kernels.

The C++ side confirms the intended contract. `PrimitiveGraph.h` exposes register/unregister, four-index connect/disconnect (`from`, source output, `to`, target input), disconnect-all, role marking, cycle validation, counts, topological order, preparation, and runtime compilation with a previous runtime for continuity. `DSPHostBindingsCore.cpp:922–1021` binds those operations and node naming into `ctx.graph`. `DSPPluginScriptHost.cpp:125–240` executes `buildPlugin`, compiles the result and requests a runtime swap. `DSPHostDeferredMutation.cpp` runs a parameter callback and recompiles the graph through a deferred mutation path. `LuaBindingsBehaviorContractHarness.cpp:488–535` checks graph counts/cycles and custom endpoint registration/listing. The old implementation uses shared node ownership, recursive locks and mutation scopes; those are implementation risks, not requirements for the new real-time engine.

## First contract to implement and test

The first real output-port slice is in place: [inverted tone texture](../../projects/graph-workspace/tone-texture-inverted.json) saves LFO `outputPort: 1`; core compilation, native project load, Wasm execution, and browser graph validation distinguish OUT, INV, and UNI. `cargo test --workspace`, `./scripts/build-wasm.sh`, `node --test web/tests/graph-output-ports.test.js`, and `npm --prefix web run build` passed on 29 September 2026. This is **partial R02 evidence**. Structural graph edits still require stopped browser playback; project scripts, atomic live structural edits, other port kinds, and browser/DAW host playback of the fixture remain open.

The next slice moved the numeric Wasm node decoder into `manifold-core` and generates the browser graph-workspace port catalog from the core node constructors and named port metadata. `scripts/update-port-catalog.sh` regenerates JavaScript and TypeScript artifacts; `npm --prefix web test` checks them for drift and probes all 24 generated codes against the actual Wasm module. The browser no longer maintains a second set of graph-workspace port types or numeric codes.

The first importable `@manifold/author` package now composes those 24 graph-workspace primitives with named typed ports, stable instance IDs, parameter defaults, immutable snapshots, and deterministic project export. [`authored-inverted-lfo.json`](../../projects/graph-workspace/authored-inverted-lfo.json) is generated by its plain [JavaScript example](../../packages/manifold-author/examples/inverted-lfo.mjs). Browser/Wasm, native processor, VST3 and CLAP callback tests load and render that one document; native and plug-in tests reopen saved state and assert the LFO's inverted output port survives. TypeScript checks reject invalid primitive/port/signal pairings. This is still **partial R01/R02**: it exports a static graph before playback; no host yet executes user JS while active, accepts a live structural transaction, or loads a full project package. Full project import rules and type coverage beyond the 24 workspace types remain open.

The Rust equivalent begins in [`manifold-native::author::GraphWorkspace`](../../crates/manifold-native/src/author.rs). It uses the same core table of 24 type IDs, ABI codes and constructor arguments that generates the JS/TS catalog. Rust calls `add`, `find`, `connect`/`disconnect` with named ports, `remove`, `set_parameter`, and `to_project_json`. The parity test assembles the JavaScript example independently in Rust, compares the parsed project values, and renders audio through the native processor. Rust nodes acquire the shared parameter defaults, and export invokes the native project reader as a final validation gate. This does not yet give either language a live transaction or a common host control runtime.

The JS package can now import and fork a plain saved graph via `GraphWorkspace.fromProject()`. A [repo example](../../scripts/author-fork-tone-texture.mjs) takes the older inverted tone-texture graph, resolves its existing numeric ports to named handles, and changes LFO INV to UNI. Its [forked project](../../projects/graph-workspace/forked-tone-texture.json) renders different audio in native and Wasm tests, and native save retains output port 2. This covers inspect/edit/export for the plain graph-workspace subset. Projects with assets, capture metadata or host bindings are rejected by this import API until their data can be preserved through edits; no such fields are silently discarded.

The native JSON reader now resolves its graph-workspace node IDs, constructor arguments, and Rust `NodeKind` from that same core catalog instead of a second 24-type constructor switch. A test parses each type (Main voice bank through its full target-bearing fixture), and retains the older variable `fixed-gain` argument as a narrow compatibility exception. This exposed a real gap: `distortion` existed in the JS/core catalog but had no native reader branch. The [JS-authored distortion project](../../projects/graph-workspace/authored-distortion.json) now renders altered audio in both native and Wasm, and native save preserves the node. Numeric parameter IDs, ranges, defaults and discrete flags now live in the Rust core catalog; generated JS metadata joins them to browser labels and choice names. The native reader and Rust builder use the same numeric entries. Display strings remain in JS because they are presentation data.

The first live authoring slice uses `@manifold/author`'s `LiveGraphSession` to propose one named route at a time and commit the JS snapshot after an AudioWorklet acknowledgement. `BrowserAudioHost` forwards the source output port; the Rust plan switches a prepared route between blocks without compiling in the callback. The browser Graph editor opts into patchable preparation only for small resource-free graphs, then enables live input selectors. A headless test initializes the actual worklet and Wasm engine, switches LFO INV to UNI while it renders, and measures different audio in the next block; a rejected host request leaves authored state unchanged. This remains **partial R02/R03**: it cannot add or remove nodes while sounding, prepare assets off-thread, transfer state into a replacement plan, or run a JS project module when a native plug-in editor is closed.

The browser session now owns acknowledged parameter changes as well as routes. It serializes both against one graph snapshot and advances one monotonic revision, so editing a parameter no longer forces the Graph editor to reconstruct the live session before its next route. A rejected parameter leaves both its authored snapshot and revision unchanged; a test interleaves accepted parameter and route requests and checks their order and saved values.

The native counterpart exposes `NativeProject::prepare_patchable` and `NativeProcessor::set_route_from`. `manifold_native::author::LiveGraphSession` stages a named Rust route edit and advances its saved document/revision after processor acceptance. Graph CLAP and VST3 now also accept a named route from their editor bridges for small resource-free graphs. A shared one-command mailbox applies the validated numeric route at the next callback block; a published generation gates the host save. VST3's callback test renders the same JS-authored fixture as a direct Rust reference before and after switching LFO INV to UNI. CLAP's callback test verifies changed audio and the published save. Both editors receive the saved connections in their presentation snapshot. Deactivation drains an unconsumed command and prepares the accepted target on reactivation. This is **partial R03 host integration**, not a native JS project runtime: editor closure leaves the route in saved DSP state, but no JS project module executes inside a native plug-in without the editor. Structural node edits, resource preparation, continuity transfer, and general project event handlers remain open.

The [DspLiveScripting default-graph port](dsp-live-scripting-port.md) is the first legacy project module imported by a generic browser page. It adds the existing stereo widener kernel to the public primitive catalog, expresses the original four-node default graph and two parameter paths in plain JS, and passes independent Rust construction plus native/Wasm signal tests. Its portable `endpoints` bind script paths to graph parameters, and explicit `hostBindings` keep their DAW slots stable across other graph edits. [`BrowserGraphHost`](../../packages/manifold-author/browser.js) supplies device I/O and acknowledged route/parameter edits to the same module used in the [generic page](../../web/generic-graph.html). The page and [updated capture](evidence/web-generic-graph-endpoints.png) prove live gain, width, and bypass with inspectable paths and slots; [matched offline timings](evidence/2026-09-29-dsp-live-native-wasm.json) compare the identical fixture in native and Wasm adapters. A native Rust `LiveGraphSession` can now stage a structural add/remove edit, compile the replacement off callback, reject stale revisions, publish at a block boundary, and hand the previous runtime back for off-callback retirement. The Rust session publisher is not yet wired into native plug-in/standalone hosts or browser/Wasm, and the old project's editor, role markings, and live script lifecycle remain open.

The [FX swap harness slice](dsp-live-scripting-port.md) adds portable `controls` for project-owned selection and inactive effect settings. Both authoring languages build its default and width-selected graphs from ordinary primitives, and Rust publishes the width addition as a prepared native transaction. CLAP and VST3 also import the selected graph while active, change stereo output, and save its project control after callback publication. The [browser audition](../../web/fx-slot-swap.html) proves both documents load in the worklet. It restarts between them because a safe browser structural publisher is still open. Project controls have not yet been connected to native plug-in automation or a JS runtime that survives editor closure.

The JS session now exposes `transaction(edit)` for add/remove/reconnect edits on a cloned graph. Its host callback receives a validated portable candidate and must acknowledge publication before the session saves the new topology. Tests check host rejection, invalid topology, and successful insertion/removal; the browser adapter has no structural callback yet. The package now includes its matching worklet and Wasm assets when packed, and an empty-directory install of the tarball imported the module and both runtime files successfully. VST3's existing active project import path was exercised with the new legacy fixture: it publishes a structural widener bypass on the next callback, changes stereo audio, and saves the replacement topology only after publication. This proves native full-project replacement through a plug-in callback, while wiring a JS project runtime to that path and safe browser structural publication remain R03/R06 gates.

The packed tarball was also installed in a separate Vite project. Its browser build emitted the package's Wasm and worklet, and Chromium started the graph and applied the legacy gain path. CLAP's active state import now has the same fixture-specific structural bypass proof as VST3: the saved four-node topology remains until callback publication; after it, audio changes and a three-node graph is saved. Both native plug-ins can replace a complete portable graph while active, though neither yet executes the JS authoring module with the editor closed.

The graph VST3 and CLAP adapters prepare replacement runtimes off the callback and publish them at a block boundary. Their host save paths follow an atomic published-generation receipt for imports and the bounded live route above. A host save reads the previous document, descriptors and value bank until publication; rejection changes none of them. If the host deactivates with a pending import or valid route, that target becomes the state prepared at its next activation. Both plug-ins test the import save boundary. This fixes the **host save generation** part of R03; a persistent native JS/TS project control runtime and continuity across arbitrary structural replacements remain open.

The next reusable CV slice exposes the existing Rust attenuverter/bias, control slew, sample/hold, and four-input CV mixer kernels as graph-workspace types. Constructor codes, port names, and numeric parameters come from the shared Rust catalog; the generated JS/TS catalog, native project reader, and browser live-route list consume those types. [`cv-utilities.mjs`](../../packages/manifold-author/examples/cv-utilities.mjs) authors a nine-node chain using all four, and [`authored-cv-utilities.json`](../../projects/graph-workspace/authored-cv-utilities.json) is its portable output. Rust authoring independently builds the same document. Native, Wasm, CLAP, and VST3 render checks exercise it; the [matched offline timing capture](evidence/2026-09-29-authored-cv-native-wasm.json) records identical native/Wasm checksums. The [browser screenshot](evidence/web-cv-utilities-live.png) shows the real remote workbench after its CV mixer route was changed while playing; an automated browser run also downloaded and reopened the accepted route while Chromium's output was verified on a private null sink. This advances R02/R05 and the bounded route part of R06; it does not provide live node creation, arbitrary graph compilation during sound, or Main's authored graph.

Compare and Range are now two more public graph primitives instead of remaining only inside Main's fixed modulation chain. [`cv-decisions.mjs`](../../packages/manifold-author/examples/cv-decisions.mjs) uses Compare's distinct GATE and TRIG outputs and Range's remap mode; Rust independently authors the same [eight-node project](../../projects/graph-workspace/authored-cv-decisions.json). The graph core advances Compare once per audio block, mapping its two-tick pulse to two blocks, then publishes both outputs to prepared control buffers. A core test checks pulse duration, distinct output ports, Range values and signal typing. A Wasm test proves GATE and TRIG produce different audio after the pulse; [matched native/Wasm output and offline timing](evidence/2026-09-29-authored-cv-decisions-native-wasm.json) records the same 460.258329261794 checksum. The [live browser capture](evidence/web-cv-decisions-live.png) shows the accepted TRIG-to-GATE reroute after the graph was loaded from its JS project, with a save verifying the selected output. The original Lua utility advances on project control updates, whose timing is not yet proven equivalent to audio-block ticks; fixed-rate control scheduling and a legacy timing comparison remain open. The browser worklet receives public type codes from the generated Rust catalog via its control thread; its older local map remains for non-public workbench types.

The first matched **v2 native versus Wasm** timing fixture is [`authored-inverted-lfo.json`](../../projects/graph-workspace/authored-inverted-lfo.json). Build with `./scripts/build-wasm.sh` and `cargo build --release -p manifold-native --example bench_authored_graph`, then run `node scripts/bench-authored-graph-native-wasm.mjs [report.json]`. The [29 September 2026 capture](evidence/2026-09-29-authored-graph-native-wasm.json) records three 48 kHz, 128-frame, 2048-block runs on a Ryzen 9 3900X, with fixture/Wasm/native binary hashes. Both adapters produced the same checksum (367.16810028618863). Across the three runs, median p50/p95/p99 were 4.28/4.59/6.46 µs for release native and 6.48/9.10/10.94 µs for Node/V8's simulated Wasm AudioWorklet path; neither exceeded the 2666.7 µs block deadline in these offline loops. These are **adapter-specific offline timings**, not browser or DAW deadline evidence. Wasm `initMs` includes module setup and is not directly comparable to native `parseMs` plus `prepareMs`. A matched legacy C++ graph, actual browser audio callback, live edit, and actual plug-in callbacks remain unmeasured under R13.

The first reusable slice should expose the same operations to Rust project modules and JS/TS control code: `create(type, stableId, settings)`, `get(stableId)`, `ports(stableId)`, `connect(fromId, outputPort, toId, inputPort)`, `disconnect(edgeId)`, `setParameter(nodeId, parameterId, value)`, `snapshot()`, and `submit(transaction)`. These names are a design sketch, not a frozen ABI. A transaction returns an accepted generation or a structured validation error; a rejected transaction changes neither saved state nor audio. The committed snapshot gives Rack, Patch, host, scripts and agents the same node/edge identities and current controls. Route-only edits may use the existing prepared-plan fast path, provided their semantics match a full transaction.

The first parity fixture should be a small non-Main legacy graph with a fan-out and a multi-output control node. The same project module must build it in Rust and JS, save/reopen it in native and browser hosts, and rewire a connection while rendering. Compare graph snapshots, errors, parameter/event timing and audio. A JSON import or code-generated hardcoded graph alone does not prove project scripting. Then use Main's `buildPlugin` topology, dynamic palette operation, and UI event as the larger fixture.

The next implementation gate is a **structural graph transaction**, not another route selector. A JS or Rust project module must add/remove a node and its typed edges while audio runs; validate and compile the proposed plan away from the callback; publish one generation at a block boundary; keep the old graph audible on rejection; and save/reopen that accepted generation in browser, CLAP, and VST3. Measure request-to-audible latency and continuity for a stable oscillator/LFO identity. Compare's GATE/TRIG outputs currently use the general CV signal type; a separate gate signal type and a fixed control-update quantum require a contract decision before claiming timing parity with old Lua projects. Main remains on the recovery ledger's M0–M5 path until this works through the public graph API.

## Open decisions and evidence still needed

- Trace the full old `Main/dsp/looper_baseline.lua`, dynamic module factories, parameter/endpoint schema and UI behavior scripts into scenario-level observations. This file only covers the contract seam, not every Main behavior or the other 27 projects.
- Check how the old graph runtime maps output indices and transfers state in practice; the header advertises both, but compatibility must be measured from actual projects. Do not reproduce old locks or callback compilation.
- Decide the Rust project module ABI/artifact path, native JS runtime, TS build path, and reload semantics with an end-to-end prototype. A browser cannot directly load arbitrary Rust source at run time.
- Measure request-to-audible latency, callback deadline distribution, memory and continuity for the chosen transaction design. The existing fixed route and post-voice graph fixture are audio oracles; they are not performance proof for a scriptable full Main graph.
