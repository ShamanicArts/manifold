## Executable proof

- [`web/tests/authoring.test.js`](../../web/tests/authoring.test.js) checks JS module export, parameter paths, Wasm mute and width behavior, and rejection of invalid values.
- The versioned `endpoints` array binds a path to one graph node parameter with a narrower public range and a default. Path lookup happens on the control side; audio still receives numeric parameter events. The array is validated against the shared primitive parameter catalog, is limited to 128 entries, and survives project import/export and native host state save. Unknown, duplicate, or out-of-range bindings fail before preparation.
- The optional `instances` array maps a stable project path to one graph node ID. A DspLiveScripting graph can name its input trim and widener, look them up after JS or Rust authoring import, export them through the browser project reader, and recover them from a native prepared host save. Removing the widener removes its registered path. This is instance lookup metadata; it does not yet implement the old script host's full module lifecycle or role registry.
- The [generic browser page](../../web/generic-graph.html) displays the shipped DspLiveScripting input trim and widener instance paths beside its endpoint controls. A headless Chromium run of the rebuilt page verified both rows and no page errors; see the [browser capture](evidence/web-generic-graph-instances.png). The page still supports the existing live parameter and route edits.
- The [FX slot browser page](../../web/fx-slot-swap.html) shows each named instance beside its selected graph snapshot; the [headless browser capture](evidence/web-fx-slot-named-instances.png) shows all eight initial rows and no page errors. The Rust and JS projects also reopen pre-instance FX slot snapshots by assigning paths to the original known node IDs. Remapped graphs use their saved paths directly.
- A Rust live transaction precomputes identity links from instance paths on the control thread and carries them into its prepared graph. At publication, the native plan transfers the eligible gain or widener history without allocating, then returns the mapping with the retired graph for off-callback disposal. Tests render a warmed widener across an ID change with sample-identical output and verify that reusing the same ID for a different path does not inherit its filter history.
- CLAP and VST3 now carry the same eligible gain and widener history through full-project imports. The native project prepares bounded node identity tables before audio starts, then each host resolves matching paths during its block-boundary swap without allocating. Both host callback tests import a renumbered DspLiveScripting widener while audio runs and compare the next stereo block against an uninterrupted reference. Continuity for other kernels remains open.
- A published endpoint range constrains the initial value, subsequent authored edits, and the native host automation descriptor. The widener primitive itself accepts 0–2, but this project's `/dsp/live/width` control and its DAW slot accept 0–1.
- The default gain and width paths bind explicitly to host slots 0 and 1 in the same project document. Rust and JavaScript authoring agree on these bindings; inserting another parameter-bearing node does not reassign them. The browser editor can retain or reassign slots, and native hosts consume the same IDs.
- [`crates/manifold-native/src/author.rs`](../../crates/manifold-native/src/author.rs) independently constructs the same graph, checks its JSON, renders native stereo audio, and stages a structural add/remove transaction with a compiled native replacement. A stale transaction is rejected and the old runtime is returned for retirement outside the callback.
- The FX harness is reconstructed independently in Rust from the JS default and width-selected fixtures. A prepared Rust transaction adds the width instance and publishes it at a block boundary; native audio changes and the retired graph is returned off callback. [Browser audition capture](evidence/web-fx-slot-swap.png) shows the width-selected project started from its portable document after the gain-only snapshot. That page restarts the worklet between snapshots; it is an audible review surface for both graphs, not proof of live browser structural replacement.
- The Rust `GraphWorkspace::from_project_json` importer rehydrates this plain authored graph from a native host save, including its paths, host slots, and project controls. The test changes selection and gate values after reopen, then prepares the edited document again. Resource-bearing graphs remain outside this importer until their asset and state contracts are carried through.
- The separate [`manifold-fx-slot-swap`](../../projects/fx-slot-swap-rust/README.md) project crate depends on the public Rust graph API. Its editor-free handler accepts the same project paths as the JS module, prepares a candidate outside audio processing, publishes only at a block boundary, and resumes event handling from a native saved document. Its test compares both JS-authored fixtures and the rendered signal. CLAP/VST3 still need a general project event dispatcher to call it while an editor is closed.
- A first-sample check exposed a native preparation discrepancy for the width-selected graph: the widener previously began at its constructor width and smoothed toward the authored 1.9. Native preparation now settles all initial parameter targets before audio starts; the widener resets its smoothed width and crossover to those targets. Native and Wasm tests independently check the original unity input/master gains and the width-selected first sample against the same authored values. The CLAP oscillator comparison uses a 1e-7 sample tolerance because its host value-bank conversion differs by a few float ulps from a direct native render.
- Native Rust authored transactions now carry gain smoothing and widener filter/correlation history for compatible instance IDs at publication, while a new gain fades in. A width amount event produces the same next-block audio as changing that parameter in place on an already running native graph. The transfer does no graph compilation or allocation on the audio side. CLAP/VST3 full-project imports and other stateful kernels still need the same explicit continuity policy.
- CLAP and VST3 tests import the gain-only FX fixture into an active plug-in, then import the width-selected fixture while processing. Both hold the published save on the old graph until the next callback, then save the 12-node graph and selected project control with changed stereo output.
- CLAP and VST3 live-import tests also save the named DspLiveScripting graph with both instance paths. Their structural bypass removes the widener and its path together; the next published state retains only the input-trim name.
- [`crates/manifold-vst3/src/graph_processor.rs`](../../crates/manifold-vst3/src/graph_processor.rs) imports this authored graph through the editor message while active, renders external stereo audio, then imports a structural bypass. The saved state stays on the old graph until the next callback and records the new three-node graph after it; the rendered signal changes.
- [`crates/manifold-clap/src/graph.rs`](../../crates/manifold-clap/src/graph.rs) performs the same active four-node to three-node import with stereo host input. Its save also waits for callback publication, and the signal changes after the replacement.

## Next boundary

`LiveGraphSession` supports parameter and prepared-route edits in browser/Wasm. Its JS `transaction(edit)` stages arbitrary topology changes and commits only after a host `applyGraph` acknowledgement; the FX harness uses it, while the browser adapter reports `structural-unavailable`. The Rust authoring session can stage a new graph and runtime away from the callback, then publish at a host block boundary. VST3 and CLAP full-project imports demonstrate active structural replacement for both the default graph and FX harness, but the Rust authoring session and JS `applyGraph` are not yet connected to those host import paths. Browser/Wasm has no equivalent safe structural publisher. Resource nodes and persistent DSP state need transfer rules by stable node ID. A reusable script runtime must keep project logic alive when a plug-in editor is closed, expose endpoint/instance lookup, and perform structural transactions through the same authored graph contract. The old ImGui editor remains an open behavior port; the FX harness now supplies a graph-composition stress fixture.
