# MIDI arpeggiator integration design

The old Main rack `arp_runtime.lua` is a clocked voice processor. It sorts held notes by pitch, expands them through 1–4 octaves, and steps at 0.25–20 Hz. Its modes are up, down, ping-pong, and random. A 30 ms capture window delays the first step so a chord entered over several callbacks starts as one sequence. Gate length is 0.05–1 of the step period. Hold latches input notes until Hold is turned off. The MIDI export observes voice gate and step-stamp changes and emits note off/on events; the original Lua advances time when `process(dt)` runs, so events land on callback boundaries.

The v2 graph already routes incoming MIDI events at sample offsets, but `ExecutionPlan::process_with_events` renders audio between externally supplied events. An arpeggiator must also create its own timed note-on and gate-close events inside those spans. Appending events at the end of a block would make the rhythm depend on block size and would apply them too late to the synth.

The implemented `MidiArpeggiator` kernel has eight held inputs, eight output lanes, and a 32-entry expanded sequence. It tracks a frame clock and the next capture, step, and gate-close deadlines. The graph render loop advances to the earlier of the next external event or internal deadline, renders that span, then routes due MIDI events before rendering the next span. `process` and `process_with_events` share the scheduler, so the arpeggiator runs even when no new input arrives. Incoming events at the same frame are handled before internal deadlines; gate offs precede new step ons. The MIDI routing stack and emitted event buffer stay preallocated.

The [migration boundary](midi-arpeggiator-migration.md) compares the old adapter's note order and callback timing through a read-only Lua probe. V2 places deadlines at exact sample offsets while the old export emits on its `process(dt)` boundaries. Four native Rust instrument fixtures compare direct Wasm, the actual AudioWorklet, and the browser comparison renderer. A graph test checks identical event frames and audio at 64-, 128-, and 256-frame blocks, including a note added inside the capture window and an all-notes-off during a gate.

The browser view shows incoming notes and Rust output trace with note, velocity, channel, and within-block offset. The on-screen keyboard supports review in the embedded browser; hardware MIDI remains optional where Web MIDI permission is available.
